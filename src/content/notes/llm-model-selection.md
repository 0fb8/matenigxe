title: "LLM のモデルは、コスト・モダリティ・レイテンシ・コンテキストウィンドウなどの属性を見比べて、用途に合うものを選ぶ"
date: 2026-11-23
tags: [ai]
---

LLM のモデルを選ぶときは、コスト、モダリティ、レイテンシ、コンテキストウィンドウ、多言語対応、モデルサイズ、カスタマイズのしやすさなどの属性を見比べ、作りたいサービスにとって大事なものを優先する。すべてで一番のモデルはないので、用途ごとに使い分ける。

属性はたがいにトレードオフになりやすい。大きくて賢いモデルほど、1回の応答に時間がかかり、料金も高くなる。そのため「とにかく一番賢いもの」を選ぶのではなく、どの属性を妥協してよいかを用途から決める。

| 属性 | 意味 |
| --- | --- |
| コスト | 入力・出力のトークン数に応じた料金 |
| モダリティ | 扱える情報の種類。テキストに加えて画像や音声なども入出力できるものをマルチモーダルという |
| レイテンシ | リクエストしてから応答が返るまでの時間 |
| コンテキストウィンドウ | 1回に入力として渡せるトークンの量 |
| 多言語対応 | 英語以外の言語をどれだけうまく扱えるか |
| モデルサイズ | パラメータ（学習で調整される重み）の数。大きいほど性能が高い傾向があるが、遅く高くなりやすい |
| カスタマイズ | ファインチューニングなどで、自分の用途向けに調整できるか |

モダリティは mode と同じ系統の語で、テキスト・画像・音声といった情報の「形式」を指す。モデルサイズはパラメータ数で表し、ニューロンの数そのものではない。パラメータ数が多いほど賢くなる傾向はあるが、学習データや学習方法でも性能は大きく変わるので、サイズだけで賢さが決まるわけではない。

用途と、優先する属性の例は次のとおり。

- リアルタイムのチャット: 待たせると使い心地が悪いので、レイテンシの小さいモデル
- 契約書の要約: 長い文書を一度に読ませたいので、コンテキストウィンドウの大きなモデル
- 写真から内容を説明する機能: 画像を入力できるマルチモーダルのモデル
- 大量の問い合わせの分類: 1件あたりの処理が単純で件数が多いので、小さく安いモデル
