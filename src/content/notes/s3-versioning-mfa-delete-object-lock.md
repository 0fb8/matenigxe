title: "S3 のバージョニングは上書きや削除の前のバージョンを残し、MFA Delete は完全な削除に MFA を求め、Object Lock は決めた期間そのバージョンを消させない"
date: 2026-11-26
tags: [aws, security]
---

S3 でオブジェクトを消されないように守る仕組みには、バージョニング、MFA Delete、Object Lock がある。バージョニングは古いバージョンを残し、MFA Delete は削除の手続きを厳しくし、Object Lock は一定期間、削除そのものをできなくする。

| 仕組み | すること | 削除できるか |
| --- | --- | --- |
| バージョニング | 上書きや削除の前のバージョンを残す | 古いバージョンも、バージョンを指定すれば消せる |
| MFA Delete | バージョンの完全な削除と、バージョニングの停止に MFA を求める | MFA があれば消せる |
| Object Lock | 決めた期間、そのバージョンの削除や上書きを禁じる | 期間中は消せない（モードによる） |

バージョニングを有効にすると、上書きしても前のバージョンが残る。バージョンを指定せずに削除すると、オブジェクトは消えずに削除マーカーが付き、見かけ上消えるだけになる。古いバージョンが増えすぎないよう、ライフサイクルルールで「古いバージョンは新しいものから3つだけ残す」「古くなって30日たったら消す」のように決めておける。

MFA Delete は、削除を慎重にさせる仕組みで、削除を禁止するものではない。有効にできるのはルートユーザーだけ。

Object Lock は WORM（Write Once Read Many）のための仕組みで、バージョニングが前提になる。保持期間の決め方に2つのモードがある。

- ガバナンスモード: `s3:BypassGovernanceRetention` の権限を持つユーザーなら、ロックを外して削除したり、期間を縮めたりできる
- コンプライアンスモード: ルートユーザーを含め、誰も期間中は削除できず、期間を縮めることもできない。一度設定すると、期間が過ぎるまで取り消せない

これとは別に、リーガルホールドがある。期限を持たないロックで、外すまで削除できない。訴訟に備えた証拠の保全など、いつまで残すかが決まっていないときに使う。保持期間とは独立していて、両方かかっているときはどちらも外れるまで消せない。

同じような仕組みは S3 以外にもあり、AWS Backup のバックアップボールトには Vault Lock（ガバナンスモードとコンプライアンスモードがある）、S3 Glacier のボールトには Glacier Vault Lock がある。
