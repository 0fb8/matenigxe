---
title: "OSPF は全ルーターが同じ LSDB を持って各自ダイクストラで経路を計算し、DR とエリアで交換の量を減らす"
date: 2026-10-12
tags: [network, routing]
---

OSPF はリンクステート型のルーティングプロトコル。同じエリアにいるルーターが、それぞれのリンクの状態（どのルーターとどのネットワークが、どのくらいのコストでつながっているか）を交換する。全員がまったく同じ地図（LSDB、Link State DataBase）を持ったうえで、各ルーターが自分を起点にダイクストラ法で最短経路を計算する。

LSDB をそろえるまで、隣のルーターとの関係は次の状態を順に進む。

| 状態 | 何が起きているか | 使うパケット |
| --- | --- | --- |
| Down | まだ相手から何も届いていない | — |
| Init | 相手の Hello を受け取った | Hello |
| 2-Way | 相手の Hello に自分が載っていた（お互いを認識した） | Hello |
| ExStart | どちらが主導して交換を進めるか（マスターとスレーブ）を決める | DBD |
| Exchange | 持っている LSA の一覧を見せ合う | DBD |
| Loading | 足りない LSA を要求して受け取る | LSR、LSU |
| Full | LSDB がそろった | — |

パケットの名前は次のとおり。

| 略称 | 正式名 | 役割 |
| --- | --- | --- |
| Hello | Hello | ネイバーを見つけ、生きていることを確かめる |
| DBD | Database Description | LSDB の目次（各 LSA のヘッダーだけ）を送る |
| LSR | Link State Request | 足りない LSA を要求する |
| LSU | Link State Update | LSA の中身を送る |
| LSAck | Link State Acknowledgment | LSU を受け取ったことを知らせる |

LSA（Link State Advertisement）は、リンクの状態を書いた1件1件の情報のこと。DBD には LSA のヘッダーだけが入り、中身は LSU で受け渡す。その後リンクに変化があれば、変わった LSA だけを LSU で全員に広める。

辺のコストは、インターフェースの帯域から決める。Cisco の既定では「基準帯域（100 Mbps）÷ インターフェースの帯域」で、結果は整数（最小 1）になる。そのため既定のままだと、100 Mbps 以上の速いリンクはすべてコスト 1 になる。速いリンクを区別したいときは、基準帯域を上げて設定する。

ルーターの数が増えると、交換の量が一気に増える。OSPF ではこれを2つの方法で抑えている。

| 方法 | 何をまとめるか | 仕組み |
| --- | --- | --- |
| DR / BDR | 1つのセグメント（Ethernet など）の中 | セグメントごとに代表ルーター（DR）と予備（BDR）を選ぶ。各ルーターは DR・BDR とだけ LSDB を交換し、DR が全員に配る |
| エリア | AS の中の、ルーターのまとまり | 詳しい LSDB を持つのは同じエリアの中だけ。ほかのエリアの経路は、まとめた形で受け取る |

DR を置かずに $N$ 台が全員と LSDB を交換すると、交換の組は $O(N^2)$ になる。DR と BDR を中心にすれば $O(N)$ で済む。なお、Hello は全員と送り合うので、ネイバーとしてはお互いを認識している。DR でも BDR でもないルーター（DROther）どうしは 2-Way で止まり、Full まで進むのは DR・BDR との間だけになる。

エリアは、エリア番号 0 のバックボーンエリアを中心にした形にする。ほかのエリアは、必ずバックボーンエリアに接続する。エリアどうしの経路は、両方にまたがるルーター（ABR）がバックボーンを経由して受け渡す。エリアの中でリンクが変わっても、ダイクストラ法での計算をやり直すのはそのエリアの中だけで済む。

OSPF には2つのバージョンがあり、IPv4 では OSPFv2、IPv6 では OSPFv3 を使う。仕組みの考え方は同じ。
