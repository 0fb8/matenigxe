AWS の AI 関連サービスは、自分でどこまで作るかによって大きく3つの層に分けられる。下の層ほど自由度が高く、上の層ほど手軽に使える。

| 層 | 主なサービス | 自分でやること |
| --- | --- | --- |
| モデルを作る基盤 | SageMaker AI、GPU などを積んだ EC2 | データの準備、学習、デプロイまで |
| 生成 AI のモデルを使う | Bedrock | 用意されたモデルを API で呼び、アプリに組み込む |
| 用途ごとの完成したサービス | Amazon Q、Rekognition、Textract など | API を呼ぶか、画面から使うだけ |

SageMaker AI は、機械学習のモデルを構築・学習・デプロイするためのプラットフォーム。sage は英語で「賢者」の意味。生成 AI に限らず、画像認識や需要予測など、機械学習全般のモデルづくりに使える。料金は主に、学習や推論に使うインスタンスの種類と稼働時間で決まる。責任共有モデルでは、モデルの中身、学習データ、インスタンスやエンドポイントの構成などを利用者が受け持つので、利用者側の比重が高い。同じ層には、EC2 に GPU や AWS 独自の機械学習用チップ（学習向けの Trainium、推論向けの Inferentia）を載せたインスタンスで、自分で環境を組んで動かす方法もある。

Bedrock は、複数の企業の生成 AI モデル（基盤モデル）をサーバーレスに API で呼び出せるサービス。Anthropic の Claude、Amazon の Nova、Meta の Llama などを選べる。入力したデータや出力が、基盤モデルの学習に使われることはない。料金は主に、入力と出力のトークン数で決まる。ほかに、一定の処理量を時間単位で確保するプロビジョンドスループットもある。サーバーやモデルの運用は AWS が受け持つので、責任共有モデルでは AWS 側の比重が高い。それでも、渡すデータの扱い、アクセス権限、出力をどう使うかは利用者の責任になる。生成 AI を使うアプリを作るときの中心になるサービスで、カスタマイズや周辺機能のための仕組みもそろっている。

- Knowledge Bases: RAG の仕組みを組み立てる
- Agents: 外部の API などを呼びながらタスクをこなすエージェントを作る
- Guardrails: 不適切な入出力をフィルターする
- ファインチューニングや継続事前学習によるモデルのカスタマイズ

一番上の層には、特定の用途向けにすぐ使えるサービスが並ぶ。

| サービス | 用途 |
| --- | --- |
| Amazon Q（Q Business、Q Developer） | 社内データに答える業務用アシスタント、開発用のアシスタント |
| Rekognition | 画像・動画の解析（物体や顔の検出など） |
| Textract | 文書からの文字や表の抽出（OCR） |
| Polly | テキストの読み上げ（音声合成） |
| Transcribe | 音声の文字起こし |
| Lex | チャットボットの構築 |
| Translate | 翻訳 |
| Comprehend | テキストの解析（感情分析、固有表現やキーフレーズの抽出など） |
| Kendra | 社内の文書をまたいで探す検索 |
| Personalize | ユーザーごとのレコメンド |
