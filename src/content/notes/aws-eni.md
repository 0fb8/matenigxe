---
title: "AWS の ENI は仮想的な NIC で、EC2 以外のサービスも VPC に ENI を置いてつながる"
date: 2026-11-15
tags: [aws, network, virtualization]
---

ENI（Elastic Network Interface）は、VPC の中に置かれる仮想的な NIC。EC2 をネットワークにつなぐための部品であるだけでなく、AWS のさまざまなサービスが VPC とつながるときの接点にもなっていて、AWS のネットワークを理解するうえで最も基本的な要素といえる。

まず物理の NIC は、コンピュータをネットワークにつなぐための部品で、拡張スロットに挿すカードの形をしていることが多い。物理層の信号とビット列の変換を受け持ち、MAC アドレスを持つのも NIC なので、IP アドレスが割り当てられるのも NIC（のインターフェース）になる。NIC を何枚も挿せば、MAC アドレスもインターフェースもそのぶん増える。

EC2 のインスタンスは、1台の物理サーバーの上に仮想化して何台も作られている。それぞれを独立にネットワークにつなぐ必要があるが、ホストの物理 NIC を1枚ずつ割り当てていてはすぐに足りなくなる。そこで、ゲストからは本物の NIC に見える ENI を用意し、仮想化の層で限られた物理 NIC を共有させている。ENI は IP アドレスやセキュリティグループを持ち、インスタンスから付け外しもできるので、柔軟に扱える。

ENI を使うのは EC2 だけではない。VPC の外にあるサービスを VPC の中から使いたいとき、VPC の中にあるかのように扱いたいときは、VPC のサブネットに ENI だけを置き、VPC 内のリソースはその ENI とやり取りする、という形がよく出てくる。名前は違っても、中身はこのパターンというものが多い。

| サービス・機能 | VPC に置かれる ENI |
| --- | --- |
| インターフェース型 VPC エンドポイント（PrivateLink） | エンドポイントの ENI。S3 などの AWS サービスや他アカウントのサービスに PrivateLink でつながる |
| VPC 内で動かす Lambda | Hyperplane ENI（関数ごとではなく、サブネットとセキュリティグループの組ごとに共有される） |
| Transit Gateway の VPC アタッチメント | アタッチしたサブネットに置かれる ENI |
| Client VPN | 関連付けたサブネットに置かれる ENI |
| RDS、ELB、EFS のマウントターゲット、NAT ゲートウェイなど | それぞれのサブネットに置かれる ENI |

まぎらわしいのは、S3 の VPC エンドポイントには **ゲートウェイ型** もあること。こちらは ENI を置かず、ルートテーブルに経路を追加する方式なので、上のパターンには当てはまらない。

こうして見ると、VPC は ENI どうしがつながったネットワークだと捉えてもよく、「何かと何かが VPC でつながっている」と言ったら、実際には ENI と ENI がつながっていると考えると見通しがよくなる。

VPC で何かを作るたびに、サブネットの指定、IP アドレスの割り当て、セキュリティグループの指定を求められて混乱しがちだが、これも同じ見方で説明がつく。どの場合も裏でやっているのは ENI の作成で、ENI はどれか1つのサブネットに置かれ、IP アドレスもセキュリティグループも ENI に紐づく。だから ENI を作る場面では、毎回この3つを聞かれるのが当然なのだ。
