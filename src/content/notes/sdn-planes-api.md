---
title: "SDN はコントロールプレーンをコントローラーに集めて一元管理し、上はノースバウンド API、下はサウスバウンド API でつなぐ"
date: 2026-10-11
tags: [network, sdn]
---

SDN（Software Defined Networking）は、ネットワーク機器の中で混ざっていた「データを転送する役目」と「転送のしかたを決める役目」を分ける考え方。転送のしかたはコントローラーが一元的に決め、ルーターやスイッチは言われたとおりに高速に転送することに専念する。

これまでのネットワークでは、ルーターやスイッチが1台ずつ、自分で経路を計算したり MAC アドレスを学習したりしていた。全部を手で設定するのは中規模以上ではとても無理なので、動的なルーティングや学習に任せる。けれども、それぞれの機器が自分で判断するので、ネットワーク全体をまとめて管理するのは難しい。原因は、1台の機器の中に2つの役目が同居していることにある。

- **データプレーン**: 届いたパケットやフレームを、表に従って次へ送る。専用チップで高速に処理する
- **コントロールプレーン**: その表（経路表や転送ルール）を作る。頭を使う部分

SDN はこれを分けて、3つの層で考える。

| 層 | 中身 | 役目 |
| --- | --- | --- |
| アプリケーション層 | セキュリティ、負荷分散などのアプリ | ネットワークをどうしたいかをコントローラーに伝える |
| コントロール層 | SDN コントローラー | 全体を見て、各機器の転送ルールを決めて配る |
| インフラストラクチャ層 | スイッチ、ルーター | 配られたルールに従って転送する |

層と層の間の API には、コントローラーから見た向きで名前がついている。

- **ノースバウンド API**: アプリケーション層とコントロール層の間（上・北向き）。REST API などが使われる
- **サウスバウンド API**: コントロール層とインフラストラクチャ層の間（下・南向き）。OpenFlow や NETCONF など

SDN と OpenFlow は同じものだと思いがちだが、OpenFlow はサウスバウンド API の代表例の1つにすぎない。SDN は機器の役目を分けるという考え方そのもので、それを実現するプロトコルや製品はいろいろある。
