date: 2026-11-23
tags: [ai]
---

機械学習のモデルは、作って終わりではなく、課題設定から監視・再学習までを繰り返すライフサイクルで扱う。この流れをパイプラインなどで標準化・自動化し、継続して回せるようにする考え方や実践を MLOps（Machine Learning Operations）という。

| 段階 | やること |
| --- | --- |
| 課題設定・要件定義 | 解く問題の種類（分類か回帰かなど）を決め、評価指標や KPI を定める |
| データ収集 | ログ、API、既存のデータベースなどから学習に使うデータを集める |
| 前処理・特徴量エンジニアリング | 欠損値の処理、クリーニング、正規化などをし、予測に役立つ特徴量を作って管理する |
| 学習 | アルゴリズムを選んで学習させる。ハイパーパラメータや結果を実験ごとに記録する |
| 評価 | 学習に使っていないデータで評価指標を測り、実際の使い方に近い形でも検証する |
| デプロイ | 本番環境に組み込み、推論に使う |
| 監視・再学習 | 本番での性能や入力データの変化を見張り、必要なら再学習する |

データの収集と前処理は、プロジェクト全体の工数の大部分を占めるといわれる。モデルの性能はデータの質に大きく左右されるうえ、現場のデータは欠けや誤りが多く、使える形に整えるのに手間がかかるため。

デプロイ後に監視が要るのは、本番のデータが時間とともに変わり、学習したときの前提からずれていく（ドリフト）から。ドリフトには主に次の2種類がある。

- データドリフト: 入力データの分布が変わる。例: 利用者の年齢層が変わる。
- コンセプトドリフト: 入力と正解の関係そのものが変わる。例: 同じ購買履歴でも、流行の変化で次に買うものが変わる。

ライフサイクルは一方通行ではなく、評価で基準を満たさなければデータ準備や学習に戻る。ドリフトを検知したら、新しいデータで学習し直す。MLOps は、ソフトウェア開発の DevOps の考え方を機械学習に当てはめたもので、データやモデルのバージョン管理、学習から評価・デプロイまでのパイプラインの自動化、本番の監視などを含む。
