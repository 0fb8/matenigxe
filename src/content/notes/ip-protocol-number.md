---
title: "IP のプロトコル番号は上に乗るプロトコルを示す 8 ビットの欄で、今の新しいプロトコルは直接乗らずに UDP の上に作られることが多い"
date: 2026-10-25
tags: [network]
---

IPv4 のヘッダーには、ペイロードが何のプロトコルかを示す 8 ビットの「プロトコル番号」の欄がある。たとえば 6 なら TCP、17 なら UDP として中身が解釈される。ただ、今新しく作られるプロトコルは、IP に直接乗せて番号をもらうのではなく、UDP の上に作られることが多い。

TCP と UDP のほかにも、IP に直接乗るプロトコルはいろいろある。

| 番号 | プロトコル | 用途 |
| --- | --- | --- |
| 1 | ICMP | エラーの通知や ping |
| 2 | IGMP | マルチキャストへの参加の通知 |
| 4 | IP in IP | IP パケットを IP パケットで包むトンネル |
| 6 | TCP | 信頼性のある通信 |
| 17 | UDP | 軽い通信 |
| 47 | GRE | いろいろなプロトコルを IP で包むトンネル |
| 50 | ESP | IPsec の暗号化 |
| 51 | AH | IPsec の認証 |
| 89 | OSPF | ルーター間の経路情報の交換 |

8 ビットなので番号は 256 個しかなく、貴重な資源といえる。ここに並ぶのは、少なくとも決められた当時には、IP に直接乗せるだけの重要さがあると考えられたプロトコルたち。

それでも、新しいプロトコルが IP に直接乗ることは、今ではほとんど期待できない。大きな理由は、途中の機器が知らない番号のパケットを通さないことにある。

- **ファイアウォール**: TCP と UDP（と ICMP くらい）しか通さない設定が多く、知らない番号のパケットは捨てられやすい。
- **NAT**: 家庭やオフィスのルーターは、TCP や UDP のポート番号を手がかりに通信を振り分ける。ポート番号を持たない知らないプロトコルは、うまく通せない。

実際、2000 年ごろに IP に直接乗る新しい L4 として SCTP（番号 132）が作られたが、こうした機器を通りにくいことが、インターネットで広まらなかった原因の1つとされる。

そこで今は、新しいプロトコルを UDP の上に作るのがふつうになっている。UDP はほとんどの機器を通れるうえ、ヘッダーが小さく、中身は自由に決められる。たとえば QUIC（HTTP/3 で使われる）や VXLAN は UDP の上に乗っている。

ちなみに IPv6 では、同じ番号を「次ヘッダー」の欄で使う。
