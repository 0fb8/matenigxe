プロンプトエンジニアリングには名前の付いたテクニックがいくつかあり、代表的なものに、例を見せる zero-shot・one-shot・few-shot、途中の考えを書かせる CoT（Chain of Thought）、決まった形のプロンプトを使い回すプロンプトテンプレートなどがある。

例の数による呼び分けは次のとおり。

| 呼び方 | プロンプトに入れる例 |
| --- | --- |
| zero-shot | なし。指示だけを書く |
| one-shot | 1個 |
| few-shot | 数個 |

LLM はプロンプトの続きとしてもっともらしい文字列を生成するので、入力と出力の組を例として見せると、出力の形式や口調がその例にそろいやすい。モデルの重みは変えず、プロンプトの中だけで振る舞いを合わせる方法なので、文脈内学習（in-context learning）とも呼ばれる。

CoT は、答えだけを出させるのではなく、途中の考えを順に書かせる方法。「順を追って考えてください」と一言添えるだけのものや、途中式つきの解答例を few-shot で見せるものがある。LLM は自分が出力したトークンを入力に足しながら次のトークンを生成するので、途中の考えを書き出すと、それが後の生成の手がかりになり、計算や推論を含む問題で正答率が上がりやすい。最近の推論モデルのように、モデル自身が回答の前に考える過程を持つものでは、プロンプトで CoT を促す効果は小さくなっている。

プロンプトテンプレートは、プロンプトの決まった部分を固定し、変わる部分だけを変数にして使い回すもの。アプリから LLM を呼ぶときによく使い、Jinja2 などのテンプレートエンジンで書くこともある。

```jinja
次の問い合わせを「請求」「技術」「その他」のどれかに分類してください。

問い合わせ: {{ inquiry }}
```

モデルの性能が上がるにつれて、細かい言い回しの工夫が結果を左右する場面は減ってきた。一方で、目的・前提・出力形式をはっきり書くことや、必要な情報をそろえて渡すことは、今でも結果に大きく影響する。
