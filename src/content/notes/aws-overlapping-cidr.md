title: "VPC の CIDR が重なるとピアリングも TGW も使えないので、片方向でよければプライベート NAT Gateway や PrivateLink でつなぎ、双方向に通信させたいならアドレスを振り直す"
date: 2026-11-22
tags: [aws, network, ip]
---

CIDR が重なった VPC 同士は、ピアリングでつなげず、TGW でも経路を区別できないので、そのままでは通信させられない。片方からだけ通信を始められればよいなら、プライベート NAT Gateway や PrivateLink で間に変換をはさんでつなぐ。双方向に自由に通信させたいなら、アドレスを振り直すしかない。

重なりは事前の計画で防ぐのが基本だが、企業合併で別々に作られたネットワークをつなぐときなど、避けられない場面もある。

NAT Gateway は、インターネットに出るときにプライベート IP アドレスをパブリック IP アドレスに変換するものとして使われることが多い。ただ、本質は IP アドレスを変換することなので、インターネットに限らない。プライベート NAT Gateway は、送信元を別のプライベート IP アドレスに変換する。重なった VPC 同士をつなぐときは、次のように組む。

1. VPC に、どことも重ならないセカンダリ CIDR を追加し、そこにサブネットを作る
2. そのサブネットにプライベート NAT Gateway と TGW のアタッチメントを置く
3. ワークロードのサブネットの RT で、相手 VPC への通信をプライベート NAT Gateway へ向ける
4. 送信元が重ならないアドレスに変換されたうえで、TGW を通って相手に届く

宛先も重ならないアドレスで見えている必要があるので、相手 VPC 側でも、重ならない CIDR のサブネットに ALB や NLB を置いて受け口にすることが多い。

この方法では、通信を始められるのは NAT Gateway を置いた側からだけ。インターネットでも、アドレス不足の対策として広まったプライベート IP アドレスと NAT が、外から通信を始められないという守りにもなっている。ここではその同じ性質が制約になる。

ほかの方法も、だいたい片方向になる。

| 方法 | つなげるもの | 向き |
| --- | --- | --- |
| プライベート NAT Gateway | NAT Gateway を置いた側から相手へ | 片方向 |
| PrivateLink（提供側に NLB、利用側にインターフェース型エンドポイント） | 特定のサービスだけ | 利用側から提供側への片方向 |
| ALB を受け口にする（HTTP / HTTPS） | 特定の Web サービスだけ | 片方向 |
| アドレスの振り直し | すべて | 双方向 |

PrivateLink では、エンドポイントの ENI は利用側の VPC のアドレスを持つので、CIDR が重なっていても関係ない。双方向に自由に通信させたいなら、重ならないようにアドレスを設計し直して移行する。そのとき、アドレスの割り当てを計画して管理するのに Amazon VPC IPAM（IP Address Manager）を使える。
