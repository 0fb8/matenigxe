---
title: "VPC エンドポイントポリシーはエンドポイントから行ける先を絞り、S3 のバケットポリシーは aws:SourceVpce などで来てよい送信元を絞る"
date: 2026-11-22
tags: [aws, security]
---

VPC エンドポイントポリシーと S3 のバケットポリシーは、どちらも IAM のポリシーの書き方で通信を絞るが、絞る向きが逆。エンドポイントポリシーは、VPC の中からエンドポイントを通って行ける先を絞る。バケットポリシーは、バケットにアクセスしてよい送信元を絞る。

| | 付ける場所 | 絞るもの |
| --- | --- | --- |
| エンドポイントポリシー | VPC エンドポイント | そのエンドポイントを通って使えるリソースや操作 |
| バケットポリシー | S3 バケット | そのバケットにアクセスしてよい送信元 |

エンドポイントポリシーは、通信の宛先を絞るプロキシのような働きをする。たとえば S3 のエンドポイントに「自社のバケットだけ許可する」ポリシーを付けておけば、VPC の中から組織の外のバケットへデータをアップロードして持ち出す、といったことを防げる。

バケットポリシーでは、条件キーで送信元を指定する。

| 条件キー | 意味 |
| --- | --- |
| `aws:SourceVpce` | 特定の VPC エンドポイントを通ってきたリクエスト |
| `aws:SourceVpc` | 特定の VPC から来たリクエスト |
| `aws:SourceIp` | 特定のパブリック IP アドレスから来たリクエスト |

VPC エンドポイントを通ってくるリクエストは送信元がプライベート IP アドレスなので、`aws:SourceIp` では絞れない。エンドポイント経由の通信を絞るときは、`aws:SourceVpce` か `aws:SourceVpc` を使う。

たとえば、特定のエンドポイントを通らないアクセスを拒否するには、次のように書く。

```json
{
  "Effect": "Deny",
  "Principal": "*",
  "Action": "s3:*",
  "Resource": ["arn:aws:s3:::example-bucket", "arn:aws:s3:::example-bucket/*"],
  "Condition": {
    "StringNotEquals": { "aws:SourceVpce": "vpce-0123456789abcdef0" }
  }
}
```

両方を組み合わせると、VPC の側からは「自社のバケットにしか行かせない」、バケットの側からは「自社の VPC からしか受け付けない」と、両方向から絞れる。
