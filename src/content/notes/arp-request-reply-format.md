---
title: "ARP のリクエストとレスポンスは同じ形式で、オペコードと各欄の埋め方だけが違う"
date: 2026-10-11
tags: [network, arp]
---

ARP のリクエストとレスポンスは、パケットの形式がまったく同じ。違うのは、種類を表すオペコード（リクエストは 1、レスポンスは 2）と、アドレスの4つの欄に何を入れるかだけ。レスポンスは、問い合わせてきた1台にだけユニキャストで返す。

IPv4 と Ethernet の組み合わせでは、ARP パケットは 28 バイトで、次の欄が並ぶ。

| 欄 | 大きさ | 中身 |
| --- | --- | --- |
| ハードウェアタイプ | 2 | Ethernet なら 1 |
| プロトコルタイプ | 2 | IPv4 なら `0x0800` |
| ハードウェア長 / プロトコル長 | 1 + 1 | MAC は 6、IPv4 は 4 |
| オペコード | 2 | 1 = リクエスト、2 = レスポンス |
| 送信元 MAC / 送信元 IP | 6 + 4 | |
| 問い合わせ先 MAC / 問い合わせ先 IP | 6 + 4 | |

アドレスの欄は、リクエストとレスポンスで次のように埋める。A（`10.0.0.1`）が B（`10.0.0.2`）の MAC を知りたい場合の例。

| 欄 | リクエスト（A → 全員） | レスポンス（B → A） |
| --- | --- | --- |
| 送信元 MAC | A の MAC | B の MAC |
| 送信元 IP | `10.0.0.1` | `10.0.0.2` |
| 問い合わせ先 MAC | `00:00:00:00:00:00`（未知） | A の MAC |
| 問い合わせ先 IP | `10.0.0.2` | `10.0.0.1` |

レスポンスでは、答えそのものは送信元の欄に入る。B は自分の MAC と IP を送信元として書き、リクエストの送信元を問い合わせ先の欄に写して返す。Gratuitous ARP や ARP プローブも、この同じ形式の欄の埋め方を変えているだけ。

レスポンスをユニキャストにできるのは、A の MAC がリクエストの送信元 MAC に書いてあり、B がそれを知っているから。B はこのとき A の IP と MAC の組み合わせを自分の ARP キャッシュにも登録するので、返事のために改めて ARP をする必要もない。答えを必要としているのは問い合わせた A だけで、ほかの機器は B の MAC を知る必要がない。ブロードキャストで返すと、関係のない全員がフレームを受け取って中身を確かめる手間がかかるので、宛先を A に絞っている。
