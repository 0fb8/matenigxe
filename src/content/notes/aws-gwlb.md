---
title: "GWLB は通信を GENEVE で包んでファイアウォールなどの仮想アプライアンスに通させる LB で、RT で GWLB エンドポイントへ向けて経路にはさむ"
date: 2026-11-22
tags: [aws, network, security]
---

GWLB（Gateway Load Balancer）は、ALB や NLB と並ぶ AWS のロードバランサーの1つで、通信をファイアウォールや IDS などの仮想アプライアンスに通してから元の宛先へ届ける。通信の経路に GWLB をはさむには、RT で通信を GWLB エンドポイントへ向ける。

アプライアンスは、英語で家電や専用の器具という意味の言葉で、ネットワークでは1つの機能に特化した専用の機器を指す。ファイアウォール専用の機器や、IDS 専用の機器などがそう。クラウドでは、その中身をソフトウェアにした仮想アプライアンスを EC2 の上で動かす。こうすると、サードパーティー製のファイアウォールなどを AWS の中でも使える。

ただ、インターネットから IGW に届いたパケットは、そのままでは RT に従って宛先へまっすぐ送られ、アプライアンスを通らない。そこで、RT で通信を GWLB エンドポイントへ向け、GWLB に渡す。

1. IGW に関連付けた RT や、サブネットの RT で、宛先への通信を GWLB エンドポイントへ向ける
2. GWLB が、パケットを GENEVE（UDP 6081 番）で包んで、ターゲットのアプライアンスへ送る
3. アプライアンスが検査し、通してよければ GWLB へ送り返す
4. GWLB は包みを外し、元のパケットを GWLB エンドポイントへ戻す
5. GWLB エンドポイントから先は、RT に従って元の宛先へ送られる

GWLB のターゲットは、アプリのサーバーではなくアプライアンスのほう。GWLB は L3 のパケットをそのまま扱い、送信元や宛先の IP アドレスを書き換えない。GENEVE で包むので、アプライアンスには元のパケットがそのまま届く。通信する両側から見ると、GWLB は経路の途中にあっても見えない。それでいて、ファイアウォールなど好きなアプライアンスをはさめる。

インターネットから入ってくる通信だけでなく、インターネットへ出ていく通信や VPC 同士の通信にも同じようにはさめる。
