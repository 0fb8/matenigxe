date: 2026-11-03
tags: [programming]
---

スキーマ（schema）は「データがどんな形をしているべきか」を決めたものだ。データの形を決めるという点では型とほぼ同じ役割で、どちらの言葉を使うかは場面ごとの慣習による部分が大きい。

語源はギリシャ語の「形」で、IT では特定のプログラミング言語に縛られない形式の定義によく使われる。

- **JSON Schema**: JSON の各キーの型や、必須かどうかを定める。
- **OpenAPI のスキーマ**: API がやり取りするリクエストとレスポンスの形を定める。
- **SQL のスキーマ**: テーブルや列の構成を定める。PostgreSQL などでは、テーブルをまとめる名前空間のことも「スキーマ」と呼ぶ。

言語の中でも、オブジェクトの形をスキーマとして書くライブラリがある。TypeScript なら Zod、Python なら Pydantic や marshmallow が有名だ。

```ts
import { z } from "zod";

const User = z.object({
  name: z.string(),
  age: z.number().int().min(0).max(20), // 0 以上 20 以下の整数
});

User.parse(JSON.parse(body)); // 形が違えば実行時にエラーになる
```

こうしたライブラリを言語の型と比べたときの利点は、主に次の2つだ。

| | TypeScript・Python の型 | スキーマのライブラリ |
| --- | --- | --- |
| チェックするとき | コードを書いたとき・コンパイル時（静的） | プログラムの実行中 |
| 外から来たデータ | 本当にその形かは確かめられない | 受け取った JSON などをその場で検証できる |
| 細かい条件 | 「整数」は書けても「0〜20 の整数」は書きにくい | 範囲・長さ・正規表現などを簡単に書ける |

TypeScript の型はコンパイルすると消える。Python の型ヒントも、実行時には基本的にチェックされない。そのため、API のレスポンスやユーザーの入力のように、実行してみるまで中身が分からないデータを確かめるにはスキーマが役に立つ。なお Pydantic は、Python の型ヒントを実行時に読み取って検証に使っている。型とスキーマがはっきり分かれているわけではない例だ。

ただし、この違いは型とスキーマの本質的な違いというより、TypeScript や Python の型の仕組みによるものだ。Idris のような依存型を持つ言語や、Liquid Haskell のような篩型（refinement type）の仕組みでは、「0 以上 20 以下の整数」も型として書ける。実行時に型の情報が残る言語もある。
