---

Global Accelerator は、2つの固定のエニーキャスト IP アドレスでクライアントの通信を受け、AWS のバックボーンでリージョンのエンドポイントへ運ぶサービス。クライアントに見せる IP アドレスは変わらず、転送先のリージョンは AWS の内側で切り替えるので、DNS の TTL を待たずにフェイルオーバーできる。

エニーキャストは、世界中のエッジロケーションが同じ IP アドレスを BGP で広告する方式。クライアントがその IP アドレスに送ると、パケットはネットワーク上でいちばん近いエッジに着く。そこから先は AWS のバックボーンで、ALB・NLB・EC2・Elastic IP アドレスなどのエンドポイントへ運ばれるので、インターネットの混雑を受けにくい。HTTP を解釈しない L4（TCP・UDP）のサービスなので、HTTP 以外の通信にも使える。

転送先は1つのリージョンに限らず、複数のリージョンに置ける。エンドポイントはリージョンごとのエンドポイントグループにまとめ、次のように振り分けを決める。

- **トラフィックダイヤル**: エンドポイントグループ（リージョン）ごとに、受け取る通信の割合を 0〜100% で決める。一部のリージョンへの割合を下げて、少しずつ移行するといった使い方ができる
- **ヘルスチェック**: 正常でないエンドポイントには送らず、ほかのリージョンへ回す

DR では、この切り替えの速さが効く。DNS でリージョンを切り替えると、クライアントやキャッシュサーバーが古い答えを TTL が切れるまで使い続けるので、反映に時間がかかる。Global Accelerator では、クライアントが使うのはいつも同じ2つの IP アドレスで、変わるのは AWS の内側の転送先だけ。そのため、障害を検知したらすぐに別のリージョンへ切り替わる。

| | DNS で切り替え | Global Accelerator |
| --- | --- | --- |
| クライアントが使う宛先 | 切り替えで IP アドレスが変わる | 2つの固定 IP アドレスのまま |
| 切り替えが効くまで | TTL が切れるまで | 検知すればすぐ |
| 扱う層 | 名前解決 | L4（TCP・UDP） |

固定 IP アドレスを持つので、ALB の前に置いて、IP アドレスで宛先を制限している送信側からも通せるようにする用途もある。
