---
title: "IAM は「誰か」を確かめる認証と「何ができるか」を決める認可の基盤で、ゼロトラストの最も基本となる構成要素"
date: 2026-10-21
tags: [security]
---

IAM（Identity and Access Management）は、利用者の ID を管理し、認証と認可をまとめて行う基盤。ゼロトラストを実現するうえで、最も基本となる構成要素の1つとされる。

ゼロトラストでは、社内ネットワークにいるかどうかでは信頼を決めず、アクセスのたびに相手を確かめる。そのとき判断の土台になるのが、「アクセスしてきたのは誰か」と「その人は何をしてよいか」という情報で、これを一手に担うのが IAM になる。

| | 問い | IAM がすること |
| --- | --- | --- |
| 認証 | 誰か | パスワードや追加の要素で本人であることを確かめる |
| 認可 | 何ができるか | その人の役割などに応じて、使えるリソースや操作を決める |

認証には、パスワードだけに頼らない方式が望ましい。

- **多要素認証（MFA）**: 知っているもの（パスワード）、持っているもの（スマートフォンなど）、本人の特徴（指紋など）のうち、異なる種類を2つ以上組み合わせる
- **リスクベース認証**: いつもと違う場所や端末、時間帯からのアクセスなど、怪しい状況のときだけ追加の確認を求める

リスクベース認証は、ゼロトラストの「状況を見てその都度判断する」という考え方とよく合う。普段どおりのアクセスでは利用者の手間を増やさず、怪しいときだけ確認を厳しくできる。

具体例としては、Microsoft のクラウドの ID 管理サービス Azure Active Directory（Azure AD）がある。社員の ID を一元管理し、多要素認証やリスクに応じたアクセス制御を提供する。なお、Azure AD は 2023 年に Microsoft Entra ID という名前に変わっている。

また、名前は似ているが、Azure AD はオンプレミスの Windows で使われてきた Active Directory（Active Directory Domain Services）とは別のサービスなので、混同しないようにしたい。
