---
title: "サーバー移行の数日前に DNS の TTL を短くしておくと、切り替え後に旧サーバーへアクセスが残る期間を短くできる"
date: 2026-11-15
tags: [dns, network]
---

サーバーを移行するときは、数日前から DNS レコードの TTL を極端に短く（たとえば数十秒〜数分に）しておく。そうすると、レコードを新サーバーの IP アドレスに書き換えたあと、古い IP アドレスにアクセスが来続ける期間を短くできる。それでも少しは旧サーバーにアクセスが来るので、移行後もしばらくは旧サーバーを動かしておく。

なぜ「数日前」なのかというと、TTL を短くしたという変更そのものも、キャッシュが切れるまでは伝わらないからだ。キャッシュ DNS サーバーは、レコードを受け取ったときの TTL のあいだ、その内容を使い続ける。もともとの TTL が 1 日なら、TTL を短く書き換えてから最大 1 日は、古い長い TTL のキャッシュが残っている。もとの TTL 以上の時間を空けてから IP アドレスを切り替えれば、どのキャッシュも短い TTL で持っている状態になり、切り替えがすぐ行き渡る。

| タイミング | やること |
| --- | --- |
| 移行の数日前 | TTL を短くする（もとの TTL 以上の時間を空ける） |
| 移行当日 | レコードを新サーバーの IP アドレスに書き換える |
| 移行後しばらく | 旧サーバーも動かしておき、残りのアクセスを受ける |
| 落ち着いたら | 旧サーバーを止め、TTL をもとの長さに戻す |

切り替える当日に TTL を短くすればよいと思いがちだが、それでは間に合わない。すでに長い TTL でキャッシュされた古い IP アドレスは、その TTL が切れるまで使われ続けるからだ。

また、TTL を短くしても旧サーバーへのアクセスがゼロになるとは限らない。TTL を守らずに長めにキャッシュするリゾルバやアプリケーションもあるので、旧サーバーをすぐ止めるとその利用者はつながらなくなる。TTL を短くしたままにしないのは、問い合わせが増えて DNS サーバーの負荷や応答の待ち時間が増えるためだ。
