---
title: "Cognito のユーザープールはアプリの利用者を認証し、ID プールはその認証結果を AWS の一時認証情報に交換して S3 などに直接アクセスさせる"
date: 2026-11-25
tags: [aws, security]
---

Amazon Cognito は、Web アプリやモバイルアプリのエンドユーザーの認証を受け持つサービス。中心になるのはユーザープールと ID プールの2つで、ユーザープールが利用者を認証し、ID プールが AWS のリソースを使うための一時認証情報を渡す。

| | ユーザープール | ID プール |
| --- | --- | --- |
| 役割 | 利用者の登録・サインインを受け持つ | 認証結果を AWS の一時認証情報に交換する |
| 渡すもの | JWT のトークン（ID トークン、アクセストークン） | アクセスキー、シークレットアクセスキー、セッショントークン |
| 使い道 | アプリへのログイン、自前の API の認可 | アプリから S3 や DynamoDB などを直接呼ぶ |

ユーザープールは、アプリ用のユーザーディレクトリ。サインアップやサインイン、パスワードのリセット、MFA などをまとめて提供する。Google などのソーシャルログインや、SAML・OIDC の外部 IdP と連携することもできる。認証が済むと JWT のトークンを発行するので、アプリや API Gateway はそれを確かめて利用者を識別する。

ただし、このトークンだけでは AWS の API は呼べない。たとえば利用者が自分の写真を S3 に直接アップロードできるようにしたいときは、ID プールを使う。ID プールは、ユーザープールや外部 IdP のトークンを受け取り、STS を通して IAM ロールの一時認証情報を返す。利用者ができることは、そのロールのポリシーで決まる。

ID プールでは、ログインした利用者用のロールと、ログインしていないゲスト用のロールを分けて設定できる。ゲストには読み取りだけを許す、といった使い分けができる。
