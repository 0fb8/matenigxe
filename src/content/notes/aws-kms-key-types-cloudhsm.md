---
title: "AWS で鍵を管理するなら基本は KMS で、鍵は AWS 所有キー・AWS マネージドキー・カスタマーマネージドキーに分かれ、PKCS#11 や専有の HSM が要るときは CloudHSM を使う"
date: 2026-11-26
tags: [aws, security]
---

AWS でエンベロープ暗号化の KEK などを管理するときも、鍵は裏側で HSM（Hardware Security Module）に保管されている。違うのは HSM をどう見せるかで、マネージドな API として使う AWS KMS（Key Management Service）と、HSM を専有して使う AWS CloudHSM がある。AWS のサービスとほぼどれとも連携するので、特別な要件がなければ KMS を使えばよい。

KMS の鍵は、誰が管理するかで3種類に分かれる。

| 種類 | 見えるか | 管理するのは | できること |
| --- | --- | --- | --- |
| AWS 所有キー | 見えない | AWS | サービスが内部で使う。利用者は何も設定できない |
| AWS マネージドキー | 見える（`aws/s3`、`aws/ebs` など） | AWS | 使われた記録は CloudTrail で見られる。キーポリシーの変更、クロスアカウントでの共有、削除はできない |
| カスタマーマネージドキー | 見える | 利用者 | キーポリシーの変更、クロスアカウントでの共有、ローテーションの設定、無効化や削除ができる |

カスタマーマネージドキーは、権限を利用者が持つ鍵のこと。鍵素材を誰が作ったかとは関係ない。コンソールで KMS に鍵を生成させたものも、外で作った鍵素材をインポートした BYOK（Bring Your Own Key）も、どちらもカスタマーマネージドキーになる。

CloudHSM は、利用者専用の HSM をクラスターとして使うサービス。KMS の HSM は複数の利用者で共有されている（論理的には分けられている）が、CloudHSM の HSM は自分だけのもので、HSM の中のユーザーや鍵も利用者が管理する。次のようなときに選ぶ。

- 規制や社内の要件で、シングルテナントの HSM が求められる
- PKCS#11（Cryptoki）や JCE などの標準的なインターフェースで、アプリから直接 HSM を呼びたい

さらに、鍵を AWS の外に置きたいときは、KMS の外部キーストア XKS（External Key Store）を使う。鍵はオンプレミスや別のクラウドの鍵管理システムに置いたまま、KMS の API で使える。暗号化や復号のたびに、KMS が外部の鍵管理システムを呼ぶ。なお、KMS の鍵を CloudHSM のクラスターに置くカスタムキーストアもある。
