---
title: "IGMP は端末がルーターにマルチキャストへの参加を伝えるプロトコルで、v1 は Report と Query だけ、v2 で Leave、v3 で送信元の指定が加わった"
date: 2026-10-25
tags: [network, multicast]
---

IGMP（Internet Group Management Protocol）は、IPv4 で端末とルーターの間でマルチキャストグループへの参加をやり取りするプロトコル。v1 は参加通知（Report）と問い合わせ（Query）だけで、v2 で離脱通知（Leave）、v3 で送信元の指定が加わった。

ルーターが知りたいのは、「このマルチキャストアドレス宛てのパケットが来たら、どのセグメントに転送すればよいか」ということ。転送先のセグメントは、0 個のことも複数のこともある。そのために、IGMP では次のメッセージをやり取りする。

| メッセージ | 向き | 意味 |
| --- | --- | --- |
| Report（参加通知） | 端末 → ルーター | このグループを受け取りたい |
| Query（問い合わせ） | ルーター → セグメント | このグループをまだ受け取りたい端末はいるか |
| Leave（離脱通知、v2 から） | 端末 → ルーター | このグループから抜ける |

v1 では、端末が Report を送ると、ルーターはそのグループ宛てのパケットをそのセグメントにも転送するようになる。ルーターは定期的に Query を送り、まだ受け取りたい端末は Report で答える。誰も答えなければ、そのセグメントへの転送をやめる。

v1 に Leave がなかったのは、ルーターが持つ状態を少なくできるためと考えられる。端末が Leave を送ってきても、同じセグメントに同じグループを受け取りたい別の端末がいるかもしれない。そのため、Leave だけで止めるには、端末ごとの参加状況を覚えておく必要がある。Query なら、「セグメントに1台でもいるか」だけを確かめればよい。実際、v1 と v2 では、同じセグメントの誰かが Report を送ったら、他の端末は自分の Report を控える決まりになっている。ルーターが気にするのは「1台以上いるか」だけだからである。

ただし、Query だけに頼ると、全員が抜けても次の Query までは不要な転送が続いてしまう。そこで v2 では Leave が加わった。Leave を受け取ったルーターは、そのグループに絞った Query をすぐにセグメントへ送り、短い時間待っても Report が返ってこなければ転送をやめる。これで、抜けたことが早く反映される。

v3 では、グループに加えて「どの送信元からのパケットを受け取りたいか（または受け取りたくないか）」まで端末が伝えられるようになった。同じグループでも、特定の送信元からのものだけを届けてもらえる。

なお、IPv6 では IGMP の代わりに MLD が同じ役割を担う。
