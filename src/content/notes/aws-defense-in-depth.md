title: "AWS のセキュリティは Shield・WAF・Network Firewall・NACL・セキュリティグループなどを通信の入り口から順に重ねて守る"
date: 2026-11-22
tags: [aws, security, network]
---

AWS のセキュリティの部品は多いが、インターネットから入ってくる通信に沿って並べると、どの層を守るものかが分かりやすい。1つが破られても次の層で止められるように重ねる（多層防御）。

| 層 | 部品の例 | 守る場所 |
| --- | --- | --- |
| DDoS | Shield | エッジやリージョンの入り口 |
| L7 | WAF | CloudFront・ALB・API Gateway など |
| VPC の出入り口 | Network Firewall、GWLB ＋サードパーティーのファイアウォール | VPC の入り口・出口や VPC 同士の通信 |
| サブネット | NACL | サブネットの境界 |
| ENI | セキュリティグループ | インスタンスなどの ENI |

**Shield** は DDoS 対策。Standard は無料で自動的に適用され、L3/L4 の一般的な DDoS を防ぐ。有料の Advanced では、DDoS で増えた料金を補償するコスト保護や、WAF と連携した L7 の DDoS への対応、AWS の専門チーム（SRT）による 24 時間 365 日の支援が付く。

**WAF** は L7 で HTTP の中身を見るので、SQL インジェクションや XSS を検知できる。リクエストの多い IP アドレスを自動でブロックするレートベースのルールや、決めた IP アドレスの一覧（IP セット）でのブロックもできる。

**NACL とセキュリティグループ**は、次の違いで使い分ける。

| | NACL | セキュリティグループ |
| --- | --- | --- |
| 状態 | ステートレス | ステートフル |
| 書けるルール | 許可と拒否 | 許可だけ |

NACL はステートレスなので、戻りの通信も別に許可しておく必要がある。戻りの宛先はクライアントのエフェメラルポート（1024〜65535 など）なので、ここを開け忘れると応答が届かない。特定の IP アドレスだけを拒否したいときは、許可しか書けないセキュリティグループではできないので、NACL か WAF の IP セットを使う。

通信の経路の外にも、次のような部品がある。

- **Route 53 Resolver DNS Firewall**: 悪性のドメインの名前解決を止める
- **VPC エンドポイントポリシー、S3 のバケットポリシー**: IAM のポリシーで、行ける先や来てよい送信元を絞る
- **VPC Traffic Mirroring**: ENI のパケットをコピーして IDS などに送る。VPC Flow Logs は通信の記録（送信元・宛先・ポートなど）だけで中身は残さないが、こちらは中身まで見られる
- **Firewall Manager**: Organizations の複数のアカウントにまたがって、WAF・Shield Advanced・セキュリティグループ・Network Firewall・DNS Firewall などの設定をまとめて管理する
