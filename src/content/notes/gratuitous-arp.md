---
title: "Gratuitous ARP は自分の IP と MAC を自分から知らせる ARP で、VRRP の切り替えではスイッチの MAC テーブルを更新する"
date: 2026-10-10
tags: [network, arp, redundancy]
---

Gratuitous ARP（GARP）は、誰にも聞かれていないのに「この IP アドレスは、この MAC アドレスです」とブロードキャストで知らせる ARP。VRRP で新しいマスターに切り替わったときにも送られる。このときの主な目的は、スイッチの MAC アドレステーブルを書き換えて、フレームが新しいマスターに届くようにすること。

ふつうの ARP は、問い合わせ（ARP リクエスト）に答える形でやり取りする。GARP では、送信元と問い合わせ先の IP アドレスに、どちらも自分の IP を入れて送る。

```text
ARP  送信元 IP = 192.168.1.1, 送信元 MAC = 00:00:5e:00:01:01
     問い合わせ先 IP = 192.168.1.1（自分自身）
     宛先 MAC = ff:ff:ff:ff:ff:ff（ブロードキャスト）
```

主な使い道は次のとおり。

| 場面 | ねらい |
| --- | --- |
| 起動時や IP アドレスを設定したとき | 同じ IP を使っている機器がいないか確かめる（返事が来たら重複） |
| 冗長化で役割が入れ替わったとき | 周りの機器に、新しい送り先を知らせる |

VRRP で切り替わったら、端末の ARP キャッシュを新しいルーターの MAC に書き換える必要がある、と思いがちだが、VRRP では仮想 IP に対応するのは仮想 MAC アドレス（`00-00-5E-00-01-<VRID>`）で、マスターが代わってもこの MAC は変わらない。そのため、端末の ARP キャッシュはそのままでよい。

問題になるのはスイッチのほう。スイッチは、仮想 MAC 宛てのフレームを、これまでどおり古いマスターがつながっていたポートへ転送しようとする。そこで新しいマスターは、仮想 MAC を送信元にした GARP を送る。スイッチはこれを見て学習し直し、仮想 MAC の行き先を新しいマスターのポートに切り替える。

一方、仮想 MAC を使わずに実際の MAC アドレスで引き継ぐ構成もある。サーバーのクラスターで IP アドレスだけを引き継ぐ場合などがそうで、そこでは GARP が端末の ARP キャッシュを書き換える役目も果たす。
