Direct Connect（DX）を使うときは、障害の検知、接続の種類、冗長化、暗号化をそれぞれ決める。検知は BGP に加えて BFD を使うと速くなる。接続は帯域と VIF の数で専用接続とホスト接続を選ぶ。冗長化はロケーションと線の本数で決め、暗号化が必要なら MACsec か VPN を重ねる。

DX で BGP が必須なのは、障害を経路に反映させるため。static ルートでも、線が物理的に切れればリンクが落ちて気づける。ただ、リンクは上がったまま途中で通信だけが止まるような障害には気づけない。BGP なら、相手から一定時間 keepalive が来なければセッションを落とし、その経路を消す。ただしこの一定時間（ホールドタイム）は標準で 90 秒なので、切り替わるまでに時間がかかる。もっと速く検知したいときは BFD（Bidirectional Forwarding Detection）を併用する。BFD は数百ミリ秒の間隔で互いの生死を確かめ合い、応答が数回続けて来なければ、1 秒ほどで障害と判断して BGP に知らせる。

接続は、AWS 側のポートを誰が持つかで2種類に分かれる。

| | 専用接続 | ホスト接続 |
| --- | --- | --- |
| ポート | 自分専用の物理ポート | パートナーのポートを分けてもらう |
| 帯域 | 1・10・100・400 Gbps | 50 Mbps〜25 Gbps ほど |
| VIF | 複数作れる | 1つだけ |
| LAG | 同じ帯域の接続を束ねられる | 使えない |

冗長化の構成には、次のようなものがある。

| 構成 | 防げる障害 |
| --- | --- |
| 2つのロケーションに2本ずつ | 線の障害とロケーションの障害の両方。最も高い |
| 2つのロケーションに1本ずつ | ロケーションの障害も防げる |
| 1つのロケーションに2本 | 線の障害は防げるが、ロケーションが SPOF になる |
| DX 1本＋ S2S VPN を待機系 | 安く済むが、切り替え中は帯域が落ちる |

DX の通信は暗号化されない。専用線なのでそのままで足りることが多いが、要件で暗号化が求められるときは次の方法がある。

- **MACsec**: L2 でフレームを暗号化する。対応するロケーションの専用接続で使える。
- **DX の上に S2S VPN を張る**: IPsec で暗号化する。VPN を通る分だけ、帯域や MTU は VPN の値に縛られる。
