---
title: "VRRP は複数のルーターで1つの仮想 IP をデフォルトゲートウェイとして見せ、マスターが落ちたらバックアップが引き継ぐ"
date: 2026-10-10
tags: [network, redundancy]
---

VRRP（Virtual Router Redundancy Protocol）は、デフォルトゲートウェイを複数のルーターで冗長化するための標準プロトコル。複数のルーターが1つの仮想 IP アドレスを共有し、端末にはその仮想 IP をデフォルトゲートウェイとして設定する。ふだんはマスターの1台だけが転送して、マスターが落ちたらバックアップが代わりを引き受ける。

端末に設定できるデフォルトゲートウェイはふつう1つなので、そのルーターが止まると外に出られなくなる（単一障害点）。VRRP では、端末から見たゲートウェイはずっと同じ仮想 IP のまま、その裏で実際に転送するルーターが入れ替わる。

- 仮想 IP には仮想 MAC アドレス（IPv4 では `00-00-5E-00-01-<VRID>`）が対応する。マスターが代わっても MAC アドレスは変わらないので、端末の ARP キャッシュを書き換えずに済む
- マスターは、自分が動いていることを定期的に（初期値は1秒ごと）マルチキャスト `224.0.0.18` で知らせる
- この知らせが一定の時間届かなくなると、バックアップのうち優先度のいちばん高いものが新しいマスターになる

```text
! Cisco の例（VRID 1、仮想 IP 192.168.1.1）
interface Gi0/0
 ip address 192.168.1.2 255.255.255.0
 vrrp 1 ip 192.168.1.1
 vrrp 1 priority 110
```

複数のルーターが同時に転送して負荷を分け合うと思いがちだが、1つの VRRP グループの中で転送するのはマスター1台だけ。いわゆるホットスタンバイ。負荷を分けたいときは、グループを2つ作って、それぞれ別のルーターをマスターにし、端末ごとにゲートウェイを分ける。

| | VRRP | HSRP |
| --- | --- | --- |
| 仕様 | 標準（RFC） | Cisco 独自 |
| 正式名称 | Virtual Router Redundancy Protocol | Hot Standby Router Protocol |
| 役割の呼び方 | マスター / バックアップ | アクティブ / スタンバイ |

2つは似ているが、互換性はない。なお、ここでいう「仮想ルーター」は、仮想マシンのような仮想化技術とは関係ない。複数の実物のルーターを1台に見せかけていることを指して「仮想」と呼んでいる。
