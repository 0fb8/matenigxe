---
title: "メールの配送は MUA → MSA → MTA → MDA という役割に分けて考えられ、実装では MSA と MTA が同じソフトのことが多い"
date: 2026-10-11
tags: [network, mail]
---

メールが送信者からメールボックスに入るまでは、MUA → MSA → MTA → MDA という4つの役割に分けて考えられる。これは役割の分け方で、実際のサーバーでは、いくつかの役割を1つのソフトがまとめて受け持つことも多い。

```text
MUA ─SMTP(587)→ MSA → MTA ─SMTP(25)→ MTA → MDA → [メールボックス]
     送信側サーバー                    受信側サーバー
```

| 役割 | 名前 | 仕事 |
| --- | --- | --- |
| MUA | Mail User Agent | 送信者にメールを書く画面を出す。メールソフトや Web メール |
| MSA | Mail Submission Agent | MUA からメールを受け付ける。送信者が本当にそのアカウントの持ち主かを確かめる |
| MTA | Mail Transfer Agent | 宛先のドメインのメールサーバーを探して、相手の MTA へ届ける |
| MDA | Mail Delivery Agent | 受け取ったメールを、受信者のメールボックスに入れる |

流れとしては、まず MUA から SMTP で MSA にメールを提出する。MSA が送信者を認証して受け付けたら、MTA の出番になる。MTA は宛先のドメインのメールサーバーを DNS（MX レコード）で調べ、相手の MTA へ SMTP で届ける。サーバーをまたいで配送するここが、いちばん華のある部分と言える。途中で別の MTA を中継することもある。受信側では、受け取ったメールを MDA がメールボックスに入れる。受信者はそこから POP3 や IMAP で読む。読むときは MUA の出番に戻る。

MSA と MTA を分けて考えるのは、受け付けるときの方針が違うからだ。MSA は自分の利用者からしか受け付けないので、認証をする。MTA は世界中のサーバーから自分宛てのメールを受け付けるので、認証はしない。そのぶん、迷惑メールの対策などは別に必要になる。

この分け方は、多少理想化されている。たとえば Postfix は、ポート 587 で MSA、ポート 25 で MTA として動き、1つのソフトで両方を受け持つ。MDA も、Postfix が自分でこなすこともあれば、Dovecot のような別のソフトに任せることもある。現実の実装がいつもこの4つにきれいに分かれているわけではないが、それぞれの段階で何をしているかを整理するのには役立つ。
