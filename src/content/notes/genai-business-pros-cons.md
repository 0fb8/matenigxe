生成 AI のビジネス上の長所は、1つのモデルで多くの仕事をこなせることと、言葉で指示するだけで使えることにある。一方で、出力が毎回変わり、理由を説明しにくく、誤りも混ざるので、同じ結果や判断の根拠が求められる場面には向かない。

| | 性質 | 内容 |
| --- | --- | --- |
| 長所 | 適応性 | 要約・翻訳・質問応答など、多くの仕事を1つのモデルでこなせる |
| | 応答性 | 自然な言葉で、すぐに応答できる |
| | シンプルさ | 専用の学習をしなくても、プロンプトで指示するだけで使える |
| 短所 | ハルシネーション | もっともらしい誤りを、事実のように出力することがある |
| | 非決定性 | 次のトークンを確率的に選ぶので、同じ入力でも出力が変わりうる |
| | 解釈性の低さ | 出力は膨大なパラメータの計算の結果で、なぜその答えになったかを説明しにくい |
| | 知識の限界 | 学習データにない情報や、学習より後の出来事は知らない |

このため、次のような場面では生成 AI 以外の方法を選ぶことが多い。

- 毎回同じ結果が必要な処理（temperature を下げても、完全に同じ出力になるとは限らない）
- 融資の審査のように、判断の理由を説明する必要があるもの
- 売上などの数値の予測や、決まった項目への分類。従来の機械学習のほうが、精度・コスト・説明のしやすさの面で有利なことが多い

導入の効果は、技術的な評価指標とは別に、ビジネスの指標でも測る。たとえば EC サイトにレコメンド用の AI を置いたなら、次のような指標を見る。

- コンバージョン率: 訪れたユーザーのうち、実際に注文した人の割合
- ARPU（Average Revenue Per User）: ユーザー1人あたりの平均売上
- CLV（Customer Lifetime Value、顧客生涯価値）: 1人の顧客が取引の期間全体でもたらす価値

CLV は、簡単には次のように見積もる。利益で見る場合は、さらに利益率を掛けたり、顧客の獲得にかかった費用を引いたりする。

$$
\mathrm{CLV} = \text{平均注文額} \times \text{購入頻度} \times \text{継続期間}
$$

EC に限らず、作業時間がどれだけ減ったか（効率）、出力がどれだけ正確か（精度）、複数の業務分野でどれだけ使えるか（ドメインをまたいだ性能）なども評価の観点になる。
