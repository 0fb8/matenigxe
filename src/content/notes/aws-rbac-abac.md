---
title: "RBAC はロールごとに権限を書くので増えるほど大変になり、ABAC はプリンシパルとリソースのタグが一致するかで判断するので、プロジェクトが増えてもポリシーを変えなくてよい"
date: 2026-11-25
tags: [aws, security]
---

アクセス制御の決め方には、ロールごとに権限を書く RBAC（Role Based Access Control）と、属性で判断する ABAC（Attribute Based Access Control）がある。AWS では、ABAC の属性にタグを使う。ABAC なら、プロジェクトが増えてもポリシーを書き換えずに済む。

RBAC は、「プロジェクト A の開発者」「プロジェクト B の開発者」のようにロールを作り、それぞれのポリシーに使ってよいリソースを書く。分かりやすいが、プロジェクトや役割が増えるたびにロールとポリシーも増え、管理が大変になる。

ABAC では、プリンシパル（ロールやセッション）とリソースの両方にタグを付けておき、「タグの値が同じなら許可する」と1つのポリシーに書く。

```json
{
  "Effect": "Allow",
  "Action": ["ec2:StartInstances", "ec2:StopInstances"],
  "Resource": "*",
  "Condition": {
    "StringEquals": {
      "aws:ResourceTag/project": "${aws:PrincipalTag/project}"
    }
  }
}
```

`project=alpha` のタグを持つプリンシパルは、`project=alpha` のインスタンスだけを操作できる。新しいプロジェクトができても、タグを付けるだけで済む。プリンシパルのタグは、IAM ロールに付けておくほか、IdP からセッションタグとして渡すこともできる。

| | RBAC | ABAC |
| --- | --- | --- |
| 何で判断するか | どのロールか | プリンシパルとリソースのタグ |
| プロジェクトが増えたとき | ロールとポリシーを足す | タグを付けるだけ |
| 弱いところ | ロールが増えると管理が大変 | タグを書き換えられると権限が変わる |

ABAC では、タグがそのまま権限になる。誰かがリソースやロールの `project` タグを書き換えれば、本来触れないリソースを操作できてしまう。そこで、タグの付け替えそのものを制限する。たとえば SCP で、決められた管理用ロール以外が `project` タグを付けたり消したりすることを Deny しておく。条件キーの `aws:TagKeys` や `aws:RequestTag` を使うと、どのタグキーを変更しようとしているかで絞れる。
