---
title: "DX を冗長化してアクティブ／スタンバイにするとき、社内から AWS への向きは Local Preference、AWS から社内への向きは AS_PATH プリペンドか AWS のコミュニティで決める"
date: 2026-11-15
tags: [aws, routing, redundancy]
---

本番環境のハイブリッドクラウドでは、AWS との接続を2本持っておくのが当然になる。2本とも DX でアクティブ／アクティブにするなら特に考えることはないが、アクティブ／スタンバイにしたいときは、どちらの経路を使わせるかを BGP で制御する。考えることは、社内から AWS へ送る向きと、AWS から社内へ送ってくる向きの2つに分かれる。

| 向き | 経路を選ぶ側 | 制御のしかた |
| --- | --- | --- |
| 社内 → AWS | 社内のルーター | Local Preference |
| AWS → 社内 | AWS | AS_PATH プリペンド、または AWS が決めているコミュニティ |

どちらも AWS 特有の機能ではなく、ふつうの BGP の知識。BGP の経路選択では、まずロンゲストマッチで、プレフィックスが長い経路が優先される。そのうえで同じ宛先の経路が複数あるときに、属性を比べてどれを使うかを決める。

社内から AWS へ送るときに経路を選ぶのは、自分たちのルーターだ。そこで、自分の AS の中で使う優先度である **Local Preference** を設定する。値が大きい経路が選ばれるので、メインにしたい DX 側を大きくしておく。

AWS から社内へ送ってくるときに経路を選ぶのは AWS なので、自分たちの設定で直接は決められない。代わりに、こちらから広告する経路の見せ方を変える。BGP は AS_PATH が短い経路を選ぶので、スタンバイ側で広告する経路だけ、AS_PATH の先頭に自分の AS 番号を何度も重ねて長く見せる。これが **AS_PATH プリペンド** で、AWS はその経路を避けるようになる。prepend は、配列の末尾に足す append の反対で、先頭に足すという意味。

ただ、AWS ではもっと直接的な方法がある。BGP では経路に **コミュニティ** というタグを付けられる。タグ自体には意味がなく、「このタグはこう扱う」とあらかじめ取り決めておいて初めて役に立つ。AWS はこの取り決めをすでに用意していて、広告する経路に決められたコミュニティを付けておくと、AWS はそれを見て経路の優先度を決める。そのため、プリペンドのような少し回りくどい方法を使わなくても、優先度をそのまま指定できる。

AWS はコミュニティを、広告した経路を AWS の中でどの範囲まで伝えるかの指定にも使っている。

なお、DX と S2S を併用するときは、AWS から社内への向きは何もしなくても DX が優先される。社内から AWS への向きだけ、Local Preference で DX 側を優先しておけばよい。
