---
title: "VPC ピアリングは2つの VPC を直接つなぐ仕組みで、届くのは相手 VPC の中だけなので、その先への転送や推移的な接続はできない"
date: 2026-11-21
tags: [aws, network, routing]
---

VPC ピアリングは、2つの VPC を1対1でつなぎ、互いのプライベート IP アドレスで通信できるようにする仕組み。ただし届くのは相手 VPC の中のリソースまでで、相手 VPC の IGW や NAT Gateway を通ってさらに先へ出ることも、ピアリングを数珠つなぎにして3つ目の VPC へ行くこともできない。

使うまでの流れは次のとおり。

1. 片方の VPC からピアリング接続（`pcx-xxxx`）をリクエストし、相手側が承認する
2. 両方の VPC の RT に、相手 VPC の CIDR を宛先、`pcx-xxxx` を行き先にしたルートを足す（戻りの通信があるので片側だけでは通らない）
3. セキュリティグループなどで相手 VPC からの通信を許可する

通信は AWS のバックボーンを通る。別リージョンの VPC や、別アカウントの VPC ともつなげる。ピアリング接続そのものに時間料金はかからないが、データ転送料は AZ やリージョンをまたぐ分だけふつうにかかる。CIDR が重なっている VPC 同士はつなげない。

相手 VPC の EC2 や RDS は、相手 VPC の中に ENI として存在しているので、ピアリング越しにそのまま使える。一方、ピアリングから入ってきたパケットは、宛先が相手 VPC の中の IP アドレスでなければ捨てられる。相手 VPC の RT に IGW や別のピアリングへの経路があっても、それに従って先へ送られることはない。そのため、次のような使い方はできない。

| やりたいこと | 結果 |
| --- | --- |
| VPC A → B の EC2 や RDS | できる |
| VPC A → B の IGW / NAT Gateway → インターネット | できない（edge-to-edge 転送は不可） |
| VPC A → B → C（A-B、B-C をピアリング） | できない（推移的ではない） |

オンプレミスのルーターは、パケットを受け取るたびに自分の RT を引き直して次へ渡すので、経路さえあれば何台でも中継できる。VPC ピアリングはルーターではなく、2つの VPC の間に引いた専用の線のようなもので、中継の役は持たない。Transit Gateway（TGW）は TGW 自身が RT を持つルーターとして働くので、送信元 VPC の RT → TGW の RT → 宛先 VPC の RT と順に引かれ、多数の VPC をまとめて中継できる。

A と C も通信させたいなら、A-C にもピアリングを張るしかない。VPC が $n$ 個あってすべてをつなぐと、ピアリングは $n(n-1)/2$ 本になる。数個の VPC なら単純で安いが、VPC が多い構成では管理しきれなくなるので、TGW を使うほうがよい。
