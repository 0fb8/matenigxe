---
title: "ALB は L7 で接続を終端して HTTP を見て振り分けるプロキシ、NLB は L4 で転送するだけの LB で、固定 IP アドレスを持つのは NLB のほう"
date: 2026-11-22
tags: [aws, network, http]
---

ALB（Application Load Balancer）は L7、NLB（Network Load Balancer）は L4 で動くロードバランサーで、それぞれの性質はほとんどこの違いから出てくる。ALB はクライアントとの接続をいったん終わらせて HTTP の中身を見るプロキシで、NLB は中身を見ずに転送する。

ALB は、クライアントとの TCP や TLS の接続を自分で受けて終端し、HTTP(S) を解釈してから、ターゲットへ新しい接続を張る。そのため、次のことができる。

- URL のパスやホスト名、ヘッダーを見て、振り分け先を変える
- AWS WAF を付けて、HTTP の中身で攻撃を防ぐ（LB の中では ALB だけ）

接続を張り直すので、ターゲットから見た送信元 IP アドレスは ALB になる。元のクライアントの IP アドレスは、X-Forwarded-For ヘッダーで渡す。

また、ALB は固定の IP アドレスを持たず、IP アドレスは変わることがある。そのためクライアントからは FQDN で指定する。送信側のファイアウォールなどで宛先を IP アドレスで制限していると、そのままでは通せない。その場合は、固定 IP アドレスを持つ NLB か Global Accelerator を ALB の前に置き、そこから ALB へ転送させる。

NLB は L4 で転送するだけなので、TCP・UDP・TLS など HTTP 以外も扱え、中身を解釈しない分だけ速い。HTTP(S) 以外のプロトコルなら、ALB は使えないので NLB を使う。TLS は、どこで復号するかを選べる。

| リスナー | NLB での扱い | ターゲットとの間 |
| --- | --- | --- |
| TLS | NLB で復号する（証明書を持たせる） | 平文の TCP、またはもう一度 TLS で暗号化 |
| TCP | 復号せずにそのまま通す（パススルー） | クライアントとの TLS がそのまま届く |

NLB は、AZ ごとに固定の IP アドレスを持つ。インターネット向けなら Elastic IP アドレスを割り当てられる。そのため、IP アドレスで宛先を制限したいときに ALB の前に置いたり、PrivateLink でサービスを提供する側の受け口にしたりする。

| | ALB | NLB |
| --- | --- | --- |
| 層 | L7 | L4 |
| 扱うもの | HTTP・HTTPS | TCP・UDP・TLS |
| 接続 | 終端して張り直す | 転送する |
| 振り分けに使えるもの | パス・ホスト名・ヘッダーなど | IP アドレスとポート |
| WAF | 付けられる | 付けられない |
| 固定 IP アドレス | なし | AZ ごとにあり |
