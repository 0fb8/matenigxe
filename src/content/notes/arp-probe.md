---
title: "ARP プローブは送信元 IP を 0.0.0.0 にして、周りのキャッシュを汚さずに IP の重複を確かめる"
date: 2026-10-11
tags: [network, arp]
---

ARP プローブは、これから使いたい IP アドレスが他の機器に使われていないかを確かめるための ARP リクエスト。送信元 IP には、使いたいアドレスではなく `0.0.0.0` を入れる。返事が来なければ重複はないので、そのアドレスを使い始め、Gratuitous ARP で周りに知らせる（ARP アナウンス）。

送信元 IP に使いたいアドレスをそのまま入れると、まだ使ってよいか分からないアドレスを、確認の段階でもう名乗ってしまうことになる。受け取った機器は送信元の IP と MAC の組み合わせを ARP キャッシュに反映するので、確認のつもりが実質的にアナウンスになってしまう。もしそのアドレスを別の機器がすでに使っていたら、周りのキャッシュが誤った MAC に書き換わり、その機器あての通信を横取りしかねない。

そこで送信元 IP には `0.0.0.0` を入れる。これはどの機器のアドレスとも重なることがなく、送信元が `0.0.0.0` の ARP は、受け取った側のキャッシュ更新には使われない。調べたいアドレスは問い合わせ先 IP に入れる。

```text
ARP プローブ
  送信元 IP = 0.0.0.0          送信元 MAC = 自分の MAC
  問い合わせ先 IP = 使いたい IP   問い合わせ先 MAC = 00:00:00:00:00:00
  （Ethernet の宛先 MAC = ff:ff:ff:ff:ff:ff）
```

全体の流れは次のとおり。

| 段階 | 送るもの | 送信元 IP | 問い合わせ先 IP |
| --- | --- | --- | --- |
| 確認（プローブ） | ARP リクエストを数回 | `0.0.0.0` | 使いたい IP |
| 使い始め（アナウンス） | Gratuitous ARP | 使いたい IP | 使いたい IP |

プローブの後に、そのアドレスを名乗る ARP が他の機器から届いたら、重複があると判断してそのアドレスは使わない。届くのは、問い合わせへの返事に限らない。他の機器がそのアドレスを送信元にしたリクエストを出していた場合も同じ扱いになる。また、別の機器が同じアドレスを同時にプローブしていた場合も、衝突として扱う。

確認を Gratuitous ARP（送信元 IP も問い合わせ先 IP も自分の IP）で済ませる方法もあるが、この方法には上で述べたキャッシュを汚す問題がある。それを避けるために、確認と使い始めを、プローブとアナウンスの2段階に分けている。
