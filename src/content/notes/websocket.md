---
title: "WebSocket は HTTP から切り替えて1本の接続を張り続け、サーバーからもいつでもデータを送れるようにする仕組み"
date: 2026-10-12
tags: [network, http, aws]
---

WebSocket は、クライアントとサーバーの間に1本の接続を張り続け、どちらからでも好きなときにデータを送れるようにする通信の仕組み。ふつうの HTTP では、クライアントが聞いたときにしかサーバーは答えられない。WebSocket なら、サーバーからもいつでもデータを送りつけられる。

例えば、ブラウザーで動くチャットを考える。誰かが発言したとき、ほかの利用者の画面にも、再読み込みをしなくてもすぐにその発言が出てほしい。ふつうの HTTP でこれをやろうとすると、主に次のような方法になる。

| 方法 | やり方 | 弱点 |
| --- | --- | --- |
| ポーリング | クライアントが数秒おきに「新着ある？」と聞く | 新着がなくても通信が発生する。間隔の分だけ遅れる |
| ロングポーリング | 新着が出るまでサーバーが返事を保留する | 1回届くたびに、リクエストを出し直す必要がある |
| WebSocket | 接続を張りっぱなしにして、サーバーから送る | 接続を保ち続けるので、サーバー側で接続を管理する必要がある |

WebSocket の接続は、HTTP のリクエストから始まる。クライアントが `Upgrade: websocket` ヘッダーを付けたリクエストを送り、サーバーが `101 Switching Protocols` を返すと、同じ TCP 接続が WebSocket に切り替わる。

```text
GET /chat HTTP/1.1
Host: example.com
Upgrade: websocket
Connection: Upgrade

HTTP/1.1 101 Switching Protocols
Upgrade: websocket
Connection: Upgrade
```

切り替わった後は HTTP のヘッダーを付けず、小さなフレーム単位でデータをやり取りする。そのため、1回あたりのやり取りが軽い。URL は `ws://`（暗号化なし）と `wss://`（TLS で暗号化）で、ポートは HTTP と同じ 80 番と 443 番を使う。

チャットのほかに、共同編集、株価などのリアルタイム表示、ブラウザーで遊ぶオンラインゲームの通信などで使われる。AWS の API Gateway にも、REST API や HTTP API と並んで WebSocket API という種類があり、接続の管理を任せられる。
