---
title: "RAG は質問に近い文書をベクトル検索で探し、プロンプトに加えてから LLM に回答を生成させる仕組みで、モデルを再学習せずに手元の情報を扱える"
date: 2026-11-23
tags: [ai]
---

RAG（Retrieval-Augmented Generation）は、質問に関係する文書を先に検索し、その内容を LLM への入力に加えてから回答を生成させる仕組み。LLM をファインチューニングしなくても、社内規定のように LLM が学習していない情報をもとに答えられる。

LLM にそのまま質問すると、学習済みの知識だけで答えるので、知らない情報は扱えず、もっともらしい誤りも混ざりやすい。RAG では、答えの根拠になる文書を外から渡すことでこれを補う。処理は名前のとおり3段階に分かれる。

| 段階 | やること |
| --- | --- |
| Retrieval（検索） | 質問に意味の近い文書を、あらかじめ作ったベクトル DB から探す |
| Augmentation（拡張） | 見つけた文書を、LLM に渡すプロンプトに加える |
| Generation（生成） | LLM が、加えられた文書を参考に回答文を生成する |

拡張は「検索で見つかった情報を、生成段階の LLM への入力に付け足す」という意味。たとえば「次の資料をもとに質問に答えてください」という指示のあとに、資料と質問を並べたプロンプトを作る。

ベクトル DB は、事前に次の手順で作っておく。

1. 社内ドキュメントを、段落などの小さな単位（チャンク）に分ける。
2. 埋め込みモデル（embedding model）で、各チャンクを意味に応じたベクトルに変換する。
3. ベクトルと元の文章を組にしてベクトル DB に保存する。

質問が来たら、質問文も同じ埋め込みモデルでベクトルにし、近いベクトルを持つチャンクを探す。近さにはコサイン類似度などを使う。

$$
\cos\theta = \frac{\boldsymbol{q} \cdot \boldsymbol{d}}{\|\boldsymbol{q}\| \, \|\boldsymbol{d}\|}
$$

意味で比べるので、文字列が一致しなくても「有給の申請方法」で「年次休暇の取得手続き」の文書を見つけられる。

埋め込みモデルは、回答を生成する LLM とは別のモデル。ただし多くはニューラルネットワーク（Transformer ベースのものも多い）で、文章を入力してベクトルを出力する。ベクトル DB は、そのベクトルを保存して近いものを素早く探す役割を受け持つ。
