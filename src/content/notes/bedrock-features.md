title: "Bedrock には、モデルを試す Playground、RAG を作る Knowledge Bases、入出力を検査する Guardrails、モデルを調整する Custom models などの機能がある"
date: 2026-11-23
tags: [aws, ai]

Amazon Bedrock は、生成 AI のモデルを API で呼べるだけでなく、生成 AI のアプリを作るのに必要な周辺の機能もまとめて提供している。bedrock は英語で「岩盤」の意味で、アプリの土台になるというニュアンスがある。

| 機能 | できること |
| --- | --- |
| Playground | 画面上で複数のモデルを試し、出力を見比べてモデル選びの参考にする |
| Knowledge Bases | RAG をマネージドで作る。文書のチャンク分割、埋め込み、ベクトル DB への保存、検索して LLM に渡す処理をまとめて任せられる |
| Agents | 外部の API やナレッジベースを呼びながら、複数のステップからなるタスクをこなすエージェントを作る |
| Guardrails | 入力と出力を検査し、有害な内容、プロンプトインジェクション、指定した話題、個人情報などを止めたり伏せたりする |
| Custom models | ファインチューニング、継続事前学習、蒸留でモデルを調整する |
| Model Evaluation | 指標による自動評価、人による評価、LLM による評価でモデルを比べる |
| Prompt Management | プロンプトを変数入りのテンプレートとして保存し、バージョン管理する |
| Flows | プロンプト、Knowledge Bases、Lambda などをつないだワークフローを作る |

蒸留（distillation）は、大きく性能の高いモデル（教師）の出力を使って、より小さいモデル（生徒）を学習させる方法。小さいモデルは速く安く動くので、用途を絞れば、性能をあまり落とさずにコストとレイテンシを下げられる。

Guardrails の検査には、有害な内容やプロンプト攻撃を見分ける分類器のような AWS 側で用意された仕組みと、禁止する単語や個人情報のパターン（正規表現）を利用者が指定する仕組みがある。どのモデルを使っていても、同じガードレールをかけられる。

料金は、オンデマンドのトークン課金が基本で、ほかに次の選び方がある。

- Provisioned Throughput: 一定の処理能力を時間単位で確保する。1か月や6か月の契約にすると割安になる。安定した大量の処理や、決まった性能が必要なときに向く。
- Batch inference: 大量のリクエストをまとめて非同期で処理する。すぐに結果が要らない処理なら、オンデマンドより安い。

Bedrock に入力したデータや出力は、基盤モデルの学習に使われず、モデルの提供元にも共有されない。
