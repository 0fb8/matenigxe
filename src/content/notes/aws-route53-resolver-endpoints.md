---
title: "VPC の DNS（Route 53 Resolver）は VPC の中からしか引けないので、オンプレミスと名前解決し合うにはインバウンドとアウトバウンドのエンドポイントを置く"
date: 2026-11-22
tags: [aws, dns, network]
---

VPC には、CIDR のネットワークアドレスに 2 を足したアドレスで DNS が用意されている。これを Route 53 Resolver と呼び、アドレスから VPC CIDR+2 と呼ぶこともある。答えるのは同じ VPC の中からの問い合わせだけなので、オンプレミスと名前解決し合うには、VPC の中にインバウンドエンドポイントとアウトバウンドエンドポイントを置く。

Route 53 Resolver は、インターネットの FQDN を解決するほか、その VPC に関連付けた Route 53 のプライベートホストゾーンの名前も解決する。ただし、どこかに DNS サーバーが1台立っているわけではない。EC2 から +2 のアドレスに問い合わせると、インスタンスが載っているホスト側でその場で処理されて答えが返る。そのため、VPC の外から +2 に問い合わせても答えは返らない。

DX や S2S VPN でオンプレミスと VPC がつながっていれば、IP アドレスを指定してのアクセスはすでにできる。FQDN で引き合うには、向きごとにエンドポイントを用意する。どちらも VPC の中に置く ENI として作る。

| 向き | 使うもの | 設定 |
| --- | --- | --- |
| オンプレミス → VPC の名前 | インバウンドエンドポイント | オンプレミスの DNS で、VPC 側のドメインの問い合わせをエンドポイントの IP アドレスへ転送する |
| VPC → オンプレミスの名前 | アウトバウンドエンドポイント | 転送ルールで、`fileserver.example.local` のような社内ドメインの問い合わせを、エンドポイント経由でオンプレミスの DNS へ送る |

VPC がたくさんあると、エンドポイントを VPC ごとに作るのは手間で、ENI ごとに料金もかかる。そこで、DNS 用の VPC を1つ作って、エンドポイントはそこにだけ置く構成がある。

- **アウトバウンド**: 転送ルールを RAM でほかのアカウントに共有し、各 VPC に関連付ける。各 VPC からの社内ドメインの問い合わせは、DNS 用 VPC のアウトバウンドエンドポイントを通ってオンプレミスへ送られる。
- **インバウンド**: オンプレミスからの問い合わせは、DNS 用 VPC のインバウンドエンドポイントで受ける。各 VPC のプライベートホストゾーンも DNS 用 VPC に関連付けておけば、まとめて答えられる。

RAM で共有するのはエンドポイントそのものではなく、転送ルールのほう。
