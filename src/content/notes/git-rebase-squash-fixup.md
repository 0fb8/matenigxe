---
title: "git rebase -i の squash はメッセージを書き直し、fixup は古い方のメッセージをそのまま使う"
date: 2026-10-18
tags: [git]
---

隣り合ったコミットを1つにまとめるには `git rebase -i` を使い、まとめたいコミットの行を `squash` か `fixup` に書き換える。どちらも変更内容は1つのコミットに合わさるが、`squash` は新しいコミットメッセージを書くためにエディタが開き、`fixup` はエディタを開かずに古い方のコミットのメッセージをそのまま使う。

```sh
git rebase -i HEAD~3
```

エディタには古いコミットが上に並ぶ。`squash`（`s`）や `fixup`（`f`）にした行は、そのすぐ上のコミットに合わさる。

```text
pick   a1b2c3d ログイン画面を追加
fixup  d4e5f6a typo を修正
squash 789abcd ログアウトボタンを追加
```

この例では、まず `a1b2c3d` に `d4e5f6a` が合わさる。続けて `789abcd` も合わさるが、こちらは `squash` なので、最後にエディタが開いてメッセージを決めることになる。

| 指定 | エディタ | できあがるコミットのメッセージ |
| --- | --- | --- |
| `squash` | 開く | 元のメッセージが並んだ状態から自分で書き直す |
| `fixup` | 開かない | 上のコミット（古い方）のメッセージ。`fixup` にした側のメッセージは捨てられる |

使い分けの目安は、まとめたあとのメッセージを考え直したいかどうか。

- `squash`: 1つの作業を細かく分けてコミットしすぎたとき。どれも意味のある変更なので、全体を表すメッセージを付け直す。
- `fixup`: 直前の作業に対する typo 修正や入れ忘れなど、ささいな直しのコミットを消したいとき。元のメッセージのままで困らない。

あとで `fixup` する前提なら、`git commit --fixup=<対象のコミット>` でコミットしておき、`git rebase -i --autosquash` を実行すると、`fixup` の行が対象のコミットのすぐ下に自動で並ぶ。

> push 済みのコミットをまとめると履歴が変わるので、`git push --force-with-lease` が必要になる。直前の1つだけを直すなら `git commit --amend` でもよい。
