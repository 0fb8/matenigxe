title: "CloudFront はエッジロケーションでコンテンツをキャッシュする CDN で、キャッシュできない通信もエッジで接続を終端して AWS のバックボーンでオリジンへ運ぶので速くなる"
date: 2026-11-22
tags: [aws, network, http]
---

CloudFront は AWS の CDN で、世界中のエッジロケーションで HTTP(S) のコンテンツを返す。キャッシュできるものはエッジから返すので速い。キャッシュできない API の応答なども、エッジで接続を受けてから AWS のバックボーンでオリジンへ取りに行くので、やはり速くなる。

オリジンには、S3、ALB、EC2、任意の HTTP サーバーなどを指定できる。画像や動画、HTML などは、一度オリジンから取ってきたら一定期間エッジにキャッシュされ、次からはエッジが直接返す。API の応答のようにキャッシュできないものでも、クライアントとの TCP や TLS の接続はエッジで終端する。エッジからオリジンまでは、インターネットの混雑を受けにくい AWS のバックボーンを通る。

クライアントにオリジンへ直接アクセスさせたくないときは、CloudFront からのアクセスだけを許可する。

| オリジン | 方法 |
| --- | --- |
| S3 | CloudFront で OAC（Origin Access Control）を設定し、バケットポリシーでそのディストリビューションからのアクセスだけを許可する |
| ALB | セキュリティグループで、CloudFront のマネージドプレフィックスリスト（AWS が管理する CloudFront の IP アドレスの一覧）からの通信だけを許可する |
| プライベートサブネットの ALB など | VPC オリジンを使い、インターネットに公開せずにオリジンにする |

ALB をプレフィックスリストで絞るだけだと、ほかの人の CloudFront からも通ってしまう。そのため、CloudFront でカスタムヘッダーを付け、ALB 側でそのヘッダーがあるかも確かめることが多い。

CloudFront に TLS を終端させるときは、ACM の証明書をバージニア北部リージョン（`us-east-1`）で発行する。CloudFront はリージョンを持たないグローバルなサービスで、証明書はこのリージョンのものを使う決まりになっている。

ほかに、次のような機能がある。

- **AWS WAF や Shield Advanced**: ディストリビューションに付けて、攻撃をエッジで防ぐ
- **地域制限**: 特定の国からのアクセスを拒否する
- **CloudFront Functions**: ヘッダーの付け替えや URL の書き換えなど、ごく軽い処理をエッジで実行する
- **Lambda@Edge**: オリジンへのリクエストの書き換えや外部へのアクセスなど、より複雑な処理をエッジで実行する
