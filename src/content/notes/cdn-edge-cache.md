---
title: "CDN は利用者の近くのエッジサーバーからコンテンツを返す仕組みで、速くなるうえにオリジンサーバーの負荷と攻撃も肩代わりする"
date: 2026-10-12
tags: [network, aws]
---

CDN（Content Delivery Network）は、世界各地にエッジサーバーを置いておき、利用者に近いエッジからコンテンツを返す仕組み。本来のコンテンツを持つサーバーをオリジンと呼ぶ。CDN を使うと、応答が速くなるうえに、オリジンへのアクセスや攻撃をエッジが肩代わりしてくれる。AWS では CloudFront がこれにあたる。

利用者がコンテンツを求めると、CDN はその利用者に近いエッジに振り分ける。振り分けには、問い合わせ元に応じて近いエッジの IP アドレスを返す DNS や、同じ IP アドレスを各地のエッジで共有するエニーキャストを使う。

エッジはコンテンツをキャッシュしている。キャッシュにあれば、そのまま返す（キャッシュヒット）。なければオリジンから取ってきて返し、次の利用者のために保存しておく。どのくらいの間キャッシュするかは、オリジンが返す `Cache-Control` ヘッダーや、CDN 側の設定で決める。

主な効果は次のとおり。

| 効果 | 理由 |
| --- | --- |
| 速くなる | 物理的に近いエッジから返すので、往復の時間が短い |
| オリジンの負荷が減る | キャッシュヒットした分は、オリジンまで届かない |
| 攻撃に強くなる | 大量のアクセスを、各地に分散したエッジで受け止める。オリジンの IP アドレスを外に見せずに済む |
| 地域ごとに出し分けられる | エッジで、国による配信の制限や、簡単な処理ができる |

攻撃に強くなる点は、CDN の大きな利点の1つ。CDN 事業者は、DDoS 攻撃を受け止める仕組みをエッジ側に用意していることが多い。CloudFront でも、DDoS への基本的な防御（AWS Shield Standard）が自動で付く。

地域ごとの出し分けとしては、特定の国からのアクセスを拒否する機能がある。また、エッジでプログラムを動かして、リクエストやレスポンスを書き換える機能（CloudFront Functions、Lambda@Edge）もある。

キャッシュできるのは、画像や CSS のように、誰が見ても同じ内容のものが中心になる。利用者ごとに内容が変わるページはキャッシュしにくい。それでも、TLS の処理をエッジで済ませたり、エッジからオリジンまで CDN 事業者の回線を通したりすることで、速くなる場合がある。
