title: "パッケージマネージャーはどの言語でもレジストリ・マニフェスト・ロックファイル・インストール先からなり、違うのは誰が作ってどう定着したか"
date: 2026-11-03
tags: [programming]
---

パッケージマネージャーは、みんなが作ったライブラリを共有して使うための仕組みで、言語が違っても形はよく似ている。違いが出るのは、それを誰が作り、どう定着したかという経緯のほうだ。

パッケージマネージャーがやることは、主に3つある。

- ライブラリを1か所に集めて共有する。
- 使いたいライブラリが依存するライブラリ、さらにその依存先まで、自動でたどって入れる（依存関係の解決）。
- どのバージョンを使っているかを記録し、ほかの環境でも同じ状態を再現できるようにする。

そのために、どれもだいたい次の4つの要素を持っている。

| 要素 | たとえると | npm（Node.js） | uv（Python） | Cargo（Rust） |
| --- | --- | --- | --- | --- |
| レジストリ | 倉庫・市場 | npm レジストリ | PyPI | crates.io |
| マニフェスト | 買い物リスト | `package.json` | `pyproject.toml` | `Cargo.toml` |
| ロックファイル | レシート | `package-lock.json` | `uv.lock` | `Cargo.lock` |
| インストール先 | 自分の部屋の棚 | `node_modules/` | `.venv/` | 共有キャッシュ（`~/.cargo/registry`） |

ロックファイルには、依存先も含めて実際に入った正確なバージョンが記録される。マニフェストに「1.2 以上」のように幅を持たせて書いても、ロックファイルがあれば全員が同じ組み合わせを使える。

定着の経緯は、大きく3つの型に分けられる。

- **コミュニティが作って定着した（Node.js・Python）**: Node.js 本体は `node_modules/` を探す仕組みや `package.json` の一部（`main` や `type` など）を読むだけだ。依存関係の管理は外部のツールに任されている。npm は Node.js とは別に作られたツールだが、早くから Node.js に同梱されたため、事実上の標準になった。そのため「Node.js のパッケージマネージャー = npm」と思いがちだが、pnpm や yarn も使える。Python は pip と venv を基本に、pipenv や Poetry などが現れてきた。最近は、仮想環境の作成からインストール、ロックまでを1つでこなす uv が広まっている。
- **言語の公式が用意した（Rust・Go）**: Rust の Cargo は言語の正式公開時から付いてくるので、どれを使うか迷うことがほとんどない。Go も公式の Go modules が標準だ。
- **標準と呼べるものがない（C/C++）**: 言語のパッケージ置き場の早い例は 1995 年に始まった Perl の CPAN で、C/C++ はそれより古い。vcpkg や Conan などはあるが決定版はなく、OS のパッケージを使ったり、手作業でライブラリを用意したりすることも多い。

パッケージマネージャーは言語だけでなく OS にもある。Ubuntu の apt、macOS の Homebrew、Windows の winget などで、こちらはアプリやコマンドを OS 全体に入れるためのものだ。
