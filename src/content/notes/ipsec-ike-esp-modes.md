---
title: "IPsec は IKE で鍵を決めて ESP で暗号化し、パケットを丸ごと包むトンネルモードと中身だけのトランスポートモードがある"
date: 2026-10-11
tags: [network, security, vpn]
---

IPsec は、IP パケットをネットワーク層（L3）で暗号化する技術。まず IKE で相手を確かめて鍵を決め、その鍵を使って ESP でパケットを暗号化する。暗号化する範囲によって、トンネルモードとトランスポートモードがある。

暗号化なら TLS のように上の層でやればよいとも思える。けれども L3 で暗号化すれば、アプリケーションが何であっても、IP で流れる通信をすべて同じように守れる。アプリ側は何も変えなくてよい。そのため、企業の拠点どうしをインターネット越しにつなぐ VPN などで使われる。

IPsec で出てくる3つのプロトコルは次のとおり。

| プロトコル | 役割 | 番号 |
| --- | --- | --- |
| IKE（Internet Key Exchange） | 相手が本物かを確かめ、暗号化に使う鍵を決める | UDP 500 |
| ESP（Encapsulating Security Payload） | パケットを暗号化し、改ざんされていないかも確かめる | IP プロトコル番号 50 |
| AH（Authentication Header） | 改ざんされていないかを確かめるだけ。暗号化はしない | IP プロトコル番号 51 |

IKE も ESP も「認証」をするので役割が重なって見えるが、確かめる対象が違う。

- **IKE の認証**: 最初に1回、通信相手の機器が本物かを確かめる
- **ESP の認証**: パケット1つ1つについて、途中で書き換えられていないか、正しい相手から来たかを確かめる

AH は暗号化をしないので、ふつうは ESP を使う。暗号化が規制されている国などで使われることがある程度。

暗号化の範囲は2通りある。

```text
元のパケット        [ IP ヘッダー | TCP など | データ ]

トランスポートモード [ IP ヘッダー | ESP | TCP など | データ ]
                                       └─ 暗号化 ─┘

トンネルモード      [ 新しい IP ヘッダー | ESP | IP ヘッダー | TCP など | データ ]
                                             └──────── 暗号化 ────────┘
```

| | トンネルモード | トランスポートモード |
| --- | --- | --- |
| 暗号化する範囲 | 元の IP ヘッダーも含めてパケット丸ごと | IP ヘッダーより後ろだけ |
| 外から見える宛先 | VPN 装置どうしのアドレス | 元の宛先そのまま |
| 主な使い方 | 拠点間 VPN（装置と装置の間） | 端末どうしの直接の通信 |

トンネルモードでは、元のパケットを丸ごと別のパケットの中に入れて運ぶ。インターネットの中に専用の通り道を掘ったように見えるので、トンネルと呼ぶ。
