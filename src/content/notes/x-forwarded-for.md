---
title: "LB が NAT するとサーバーには LB の IP アドレスしか見えないので、HTTP では X-Forwarded-For ヘッダーに元の送信元 IP アドレスを書いて渡す"
date: 2026-11-15
tags: [network, http]
---

ロードバランサー（LB）が送信元 IP アドレスを自分のものに変換（NAT）すると、サーバーからはすべての通信が LB から来たように見え、利用者を IP アドレスで見分けられなくなる。HTTP なら、LB が X-Forwarded-For（XFF）ヘッダーにもとの送信元 IP アドレスを書き足して渡すことで、サーバーが利用者を識別できる。

名前のとおり「誰のために転送したか（forwarded for）」を示すヘッダーだ。先頭の X- は、もともと標準外の拡張ヘッダーに付ける慣習の名残で、意味を気にする必要はあまりない。

LB が多段になっているときは、各 LB が自分の受け取った通信の送信元 IP アドレスを、カンマ区切りで後ろに追加していく。

```
X-Forwarded-For: 203.0.113.10, 198.51.100.5
```

この例では、先頭の `203.0.113.10` がもとの利用者、`198.51.100.5` が1段目の LB だ。最後の LB の IP アドレスはヘッダーには入らず、サーバーから見た TCP の送信元として分かる。

注意点は、これが HTTP、つまり L7 の中身の書き換えだということだ。

- **LB が L7 を解釈できる必要がある**: IP アドレスとポートだけを見て振り分ける L4 の LB では、ヘッダーを書き足せない。
- **HTTPS では LB で TLS を終端する必要がある**: 暗号化されたままではヘッダーを読み書きできない。LB にサーバー証明書と秘密鍵を持たせ、LB で一度復号してからヘッダーを足す。

また、XFF は利用者側でも自由に書けるヘッダーなので、信頼できる LB が付けた部分だけを信じる必要がある。
