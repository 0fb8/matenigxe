---
title: "NTP の monlist は小さな問い合わせで大量の応答が返るので、送信元を詐称した DDoS の踏み台にされる"
date: 2026-10-18
tags: [network, security]
---

NTP サーバーの monlist は、そのサーバーと最近やり取りした相手の一覧（最大 600 件ほど）を返す管理用の問い合わせ。小さなリクエストに対して大きな応答が返るので、送信元 IP アドレスを詐称したリフレクション（反射）型の DDoS 攻撃に悪用される。対策は、外部からの管理用の問い合わせを受け付けないことか、少なくとも monlist を無効にしておくこと。

攻撃の流れは次のとおり。

1. 攻撃者が、インターネットに公開されている NTP サーバーに monlist のリクエストを送る。このとき送信元 IP アドレスを、攻撃したい相手のアドレスに書き換えておく。
2. NTP サーバーは、リクエストの送り主だと思って、被害者に大きな応答を返す。
3. これを多数の NTP サーバーに何度も繰り返させると、被害者に大量の通信が集中する。

NTP が狙われやすい理由は3つある。

- **増幅率が高い**: 数十バイトの問い合わせに対して、何倍、何百倍もの応答が返る。攻撃者は自分の回線をあまり使わずに、大きな通信量を生み出せる。
- **UDP を使う**: TCP のようなハンドシェイクがないので、送信元を詐称したリクエストでもそのまま処理されてしまう。
- **公開サーバーが多い**: 時刻合わせのために外部へ公開されている NTP サーバーがたくさんある。

管理者が踏み台にされないための対策は次のとおり。

| 対策 | 内容 |
| --- | --- |
| 外部からの問い合わせを制限する | 公開する必要がなければ、外部からのリクエストを受け付けない |
| monlist を無効にする | 時刻の配信は続けつつ、管理用の問い合わせだけ止める。monlist を削除済みの新しいバージョンに更新する方法もある |

ntpd の設定ファイルでは、たとえば次のように書く。

```text
# 監視機能（monlist）を止める
disable monitor
# 時刻の配信は許可し、状態の問い合わせは拒否する
restrict default nomodify notrap nopeer noquery
```

monlist だけを止めた場合も、通常の時刻リクエストは受け付けるので、送信元を詐称したリクエストへの応答が被害者に届くこと自体は起こりうる。ただし通常の時刻の応答はリクエストとほぼ同じ大きさで、増幅にならない。攻撃者にとってうまみがほとんどないので、実用上の問題は小さい。
