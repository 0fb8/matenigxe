---
title: "TCP は全二重で、A→B と B→A で別々のシーケンス番号を持ち、3ウェイハンドシェイクは2本の SYN と2本の ACK を3つに詰めたもの"
date: 2026-10-12
tags: [network, tcp]
---

TCP は全二重なので、1本の接続の中に A→B と B→A の2つの流れがあり、それぞれが独立したシーケンス番号の空間を持つ。1つのセグメントには、自分の流れの Seq と、相手の流れに対する Ack が同時に載る。

A が B に送るセグメントを例にすると、2つの役割を兼ねている。

| 欄 | どちらの流れの話か | 意味 |
| --- | --- | --- |
| Seq | A→B | A が送るデータの位置 |
| Ack | B→A | B から受け取ったデータへの返事 |

2つの流れは互いに独立していて、番号もそれぞれの初期値（ISN）から別々に数える。B が A に送るときは、この関係が逆になる。

3ウェイハンドシェイクもこの見方で読める。必要なのは「A→B の SYN とその ACK」と「B→A の SYN とその ACK」の4つで、真ん中の2つを1つのセグメントにまとめて送るので、3回になる。

```text
1. A → B  SYN  Seq = a                 （A→B の流れを開始）
2. B → A  SYN  Seq = b                 （B→A の流れを開始）
          ACK  Ack = a + 1             （A→B の SYN への返事）
3. A → B  ACK  Seq = a + 1, Ack = b + 1（B→A の SYN への返事）
```

SYN は番号を1つ消費するので、返事の Ack は相手の ISN に 1 を足した値になる。3番目のセグメントは B→A の流れへの返事が目的なので、データを載せないことが多い。ただし、これで A→B の流れが終わるわけではない。A の Seq は `a + 1` のままで、A はこの後も同じ流れでデータを送り続けられる。一方の流れを閉じるのは FIN を送ったときで、閉じるときも2つの流れを別々に閉じる。
