---
title: "エンベロープ暗号化はデータを DEK で暗号化し、その DEK だけを KMS や HSM から出ない KEK で暗号化して、大きなデータでも鍵を閉じ込めたまま守る"
date: 2026-11-25
tags: [security, aws]
---

エンベロープ暗号化は、鍵を2段階に分ける暗号化のやり方。データは DEK（Data Encryption Key）で暗号化し、その DEK を KEK（Key Encryption Key）で暗号化する。KEK は KMS や HSM の中から出さない。どちらの鍵も共通鍵で、保存するデータの暗号化には、公開鍵暗号よりずっと速い共通鍵暗号を使う。

鍵は、生成から暗号化・復号、ローテーションまで、KMS や HSM のような安全な場所に閉じ込めておくのがいちばん安全。ただ、何テラバイトもあるデータをすべてその中へ送って暗号化させるのは現実的ではない。ネットワークを通す量が膨大になり、処理の速さも費用も見合わない。AWS KMS の `Encrypt` API も、一度に暗号化できるのは 4 KB までになっている。

そこで、大きなデータの暗号化は手元の DEK で行い、KMS や HSM には小さな DEK の暗号化だけを任せる。

| 鍵 | 暗号化するもの | 置き場所 |
| --- | --- | --- |
| DEK | データそのもの | 暗号化した形でデータのそばに保存する。平文の DEK は使い終わったら消す |
| KEK | DEK だけ | KMS や HSM の中から出さない |

AWS KMS では、次のように動く。

1. `GenerateDataKey` を呼ぶと、KMS は DEK を生成し、平文の DEK と、KMS キー（KEK）で暗号化した DEK の両方を返す
2. 平文の DEK でデータを暗号化し、平文の DEK はメモリから消す
3. 暗号化したデータと、暗号化した DEK をいっしょに保存する
4. 復号するときは、暗号化した DEK を KMS の `Decrypt` に渡して平文の DEK を受け取り、それでデータを復号する

暗号化した DEK が盗まれても、KEK がなければ DEK は取り出せない。KEK は KMS や HSM の外に出ないので、使うには KMS などの権限が必要になる。また、KEK をローテーションするときも、データ全体を暗号化し直す必要はない。

名前の「エンベロープ」は封筒のこと。DEK を KEK で包み、暗号化したデータに添えておく様子を、封筒に入れることにたとえている。KEK で暗号化するのは DEK だけで、暗号化したデータをさらに暗号化するわけではない。
