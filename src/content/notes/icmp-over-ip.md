---
title: "ICMP は L3 と呼ばれるが、Ethernet に直接は乗らず IP の上（プロトコル番号 1）に乗る"
date: 2026-10-08
tags: [network, icmp]
---

ICMP はネットワーク層（L3）のプロトコルとして紹介されることが多い。けれども、パケットの中では IP と横並びではなく、IP の上に乗っている。Ethernet が運ぶのはあくまで IP で、ICMP はその IP のデータ部分に入る。

ヘッダーの中で次に何が続くかを示す番号を見ると、入れ子の関係がよく分かる。

| ヘッダーの欄 | 値 | 次に続くもの |
| --- | --- | --- |
| Ethernet の EtherType | `0x0800` | IPv4 |
| Ethernet の EtherType | `0x0806` | ARP |
| IPv4 のプロトコル番号 | `1` | ICMP |
| IPv4 のプロトコル番号 | `6` | TCP |
| IPv4 のプロトコル番号 | `17` | UDP |

```text
[ Ethernet ヘッダー | IPv4 ヘッダー（プロトコル番号 = 1）| ICMP メッセージ ]
```

EtherType に ICMP を指す値はない。ICMP は、TCP や UDP と同じ欄（IPv4 のプロトコル番号）で指定される。この見方では、IP と同じ階層だとは言いにくい。比べると、ARP は EtherType で直接指定されるので、Ethernet の上にじかに乗っている。

それでも ICMP が L3 に分類されるのは、役割の点で IP の一部だから。ICMP は、宛先に届かなかったことや TTL が切れたことなどを知らせて、IP の通信を支える。ICMP の仕様にも、IP を実装するなら ICMP も必ず実装するように書かれている。またポート番号を持たず、アプリケーション同士の通信を運ぶわけでもない。この点で、L4 の TCP や UDP とは性格が違う。

まとめると、ICMP は

- **カプセル化**の点では IP の上に乗る（IP の中身として運ばれる）
- **役割**の点では IP を補うネットワーク層のプロトコル

のように、どちらの面から見るかで印象が変わる。ちなみに IPv6 では ICMPv6 を使い、IPv6 ヘッダーの「次のヘッダー」の欄に `58` を入れて指定する。
