---
title: "AWS Network Firewall は各 VPC に置く分散型と検査用 VPC に集める集約型があり、集約型では TGW のアプライアンスモードが要る"
date: 2026-11-22
tags: [aws, security, routing]
---

AWS Network Firewall は、AWS が管理してくれるファイアウォールで、VPC の出入り口や VPC 同士の通信を検査する。置き方には、VPC ごとに置く分散型と、検査用の VPC に集める集約型がある。集約型では、TGW の検査用 VPC のアタッチメントでアプライアンスモードを有効にする。

GWLB ＋サードパーティーのファイアウォールでは、アプライアンスの EC2 を自分で運用し、GWLB エンドポイントを RT で経路にはさんでいた。Network Firewall では、アプライアンスの部分を AWS が持ち、自分で用意するのはエンドポイントを置くサブネットと RT だけになる。

| 置き方 | 構成 | 向いている場面 |
| --- | --- | --- |
| 分散型 | 各 VPC の AZ ごとにファイアウォール用のサブネットを作ってエンドポイントを置き、RT で通信をそこへ向ける | VPC が少ない、VPC ごとにルールを変えたい |
| 集約型 | 検査用の VPC にだけファイアウォールを置き、各 VPC からは TGW で検査用 VPC を通す | VPC が多い、ルールを1か所で管理したい |

集約型でアプライアンスモードが要るのは、行きと帰りを同じファイアウォールに通すため。TGW は、通常はパケットを送ってきた AZ と同じ AZ のアタッチメントの ENI へ送ろうとする。そのため、AZ-a の VPC から AZ-b の VPC への通信は、行きは検査用 VPC の AZ-a、帰りは AZ-b のファイアウォールを通ってしまうことがある。ステートフルな検査では、帰りのパケットを見たファイアウォールが行きを知らないので、捨ててしまう。アプライアンスモードを有効にすると、TGW は1つのフローの行きと帰りを同じ AZ のアタッチメントに送るので、同じファイアウォールを通る。

DNS Firewall との違いも押さえておく。DNS Firewall は名前解決の段階で止めるので、IP アドレスを直接指定されたり、別の DNS サーバーを使われたりすると、すり抜けられる。より確実に止めたいなら、通信そのものを検査する Network Firewall を使うか、両方を組み合わせる。
