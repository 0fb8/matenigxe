---
title: "HTTP の GET は URL のクエリ文字列で、POST はリクエストボディでデータを送る"
date: 2026-10-10
tags: [network, http]
---

HTTP でサーバーにデータを渡すとき、GET では URL の末尾の `?` から後ろ（クエリ文字列）に入れる。POST ではリクエストボディ（ヘッダーの後ろの本文）に入れる。

```http
GET /search?q=vlan&page=2 HTTP/1.1
Host: example.com
```

```http
POST /login HTTP/1.1
Host: example.com
Content-Type: application/x-www-form-urlencoded
Content-Length: 29

user=alice&password=secret123
```

GET のデータは URL の一部なので、ブラウザのアドレス欄、履歴、ブックマーク、サーバーやプロキシのアクセスログ、別のサイトへ移るときに送られる Referer ヘッダーなど、いろいろな所に残る。POST のボディはふつうアクセスログに残らず、履歴にも出ない。

| | GET | POST |
| --- | --- | --- |
| データを入れる場所 | URL（クエリ文字列） | リクエストボディ |
| 主な用途 | データを取ってくる（検索、ページの表示） | データを送って処理させる（ログイン、投稿） |
| 同じリクエストを繰り返したとき | 結果は変わらない前提 | 投稿が二重になるなど、結果が変わりうる |
| キャッシュやブックマーク | できる | ふつうはできない |
| データの量 | URL の長さの上限に縛られる | 大きなデータやファイルも送れる |

GET は URL のパスに情報を入れる、と言われることもあるが、データを入れるのは正確にはパスの後ろのクエリ文字列。ただし `/users/123` のように、パスそのものに ID などを入れる設計もよくある。

POST ならデータが暗号化されて安全だと思いがちだが、POST は URL に出ないだけで、ボディは平文のまま流れる。盗み見を防ぐには HTTPS が必要。パスワードなどを GET で送ってはいけない理由は、通信が暗号化されないからではなく、ログや履歴に残ってしまうから。
