---
title: "IPv6 はアドレスを増やしただけでなく、アドレスの割り当てとスコープ制御を切り分けるなど設計を整理している"
date: 2026-10-10
tags: [network, ipv6]
---

IPv6 はアドレス枯渇への対策として語られることが多い。けれども、変わったのはアドレスの数と書き方だけではない。IPv4 で混ざり合っていた役割を切り分けるように、設計が整理されている。

| | IPv4 | IPv6 |
| --- | --- | --- |
| 通信の届く範囲の制御 | プライベート IP と NAT が、結果として範囲を区切っていた | 1つのインターフェースに範囲（スコープ）の違うアドレスを複数持たせる。外からの通信を止めるのはファイアウォールの役目 |
| ブロードキャスト | あり（ARP など） | なし。マルチキャストで必要な相手にだけ送る |
| アドレス解決 | ARP | NDP（ICMPv6 の機能の1つ） |
| アドレスの決め方 | DHCP サーバーからもらう | ルーターの RA でプレフィックスを知り、自分で作る（SLAAC）。重複していないかは NDP で確かめる |

IPv4 のプライベート IP と NAT は、アドレス不足をしのぐために入ったもの。それが、外から内側へ直接つながらないという、範囲を区切る効果もたまたま持っていた。NAT があるから安全だと思いがちだが、それは本来の目的ではない。IPv6 ではアドレスが足りないことを気にしなくてよいので、アドレスの割り当てと、どこまで通信を通すかの制御を分けて考える。

1つのインターフェースが持つ主なアドレスは次のとおり。

- **リンクローカルアドレス**（`fe80::/10`）: 同じリンク（セグメント）の中だけで使う。ルーターや近くの機器とのやり取り（RA や NDP）はこれで行う
- **グローバルアドレス**（`2000::/3`）: インターネットで通用する。家庭の機器も持つ
- **ユニークローカルアドレス**（`fc00::/7`）: 組織の中だけで使う。IPv4 のプライベート IP に近いが、使われる場面は多くない

ブロードキャストは、関係のない機器にも届いてしまう。受け取った機器は、自分宛てかどうかを OS まで上げて調べなければならず、むだが多い。IPv6 ではブロードキャストをやめ、ARP の代わりに NDP がマルチキャストで問い合わせる。

ただし DHCPv6 がなくなったわけではない。企業ネットワークでアドレスを管理したいときや、ISP が家庭のルーターにプレフィックスを配るとき（DHCPv6-PD）には今も使われている。
