---
title: "MTU はリンクごとに決まる値で、AWS では場所によって 9001・8500・1500 バイトと違い、経路全体ではいちばん小さい値が Path MTU になる"
date: 2026-11-21
tags: [network, ip, aws]
---

MTU（Maximum Transmission Unit）は、1つのリンクが一度に運べる IP パケットの最大サイズ。値は L2 の作りで決まり、1500 バイトに決まっているわけではない。いくつものリンクを通る通信では、その中でいちばん小さい MTU が経路全体の上限になる。これを Path MTU という。

IP は L2 の中身に依存せず、リンクごとに違う MTU をそのまま受け入れて動く。1500 バイトは、Ethernet のフレームがペイロードに 1500 バイトを割り当てていることから来ている。インターネットではこれが標準なので、IPv4 と TCP のヘッダーを 20 バイトずつ引いた MSS 1460 バイトもよく見る。社内のネットワークやクラウドでは L2 を自由に作れるので、1500 バイトを超えるフレーム（ジャンボフレーム）を使うこともある。MTU が大きいとパケットあたりのヘッダーの割合が減るので、スループットが上がる。

AWS では、通る場所によって MTU が違う。

| 場所 | MTU |
| --- | --- |
| VPC の中（対応するインスタンス同士） | 9001 バイト |
| Transit Gateway（VPC・Direct Connect・ピアリングなど） | 8500 バイト |
| Direct Connect | 1500 または 9001 バイト（transit VIF は 8500 バイト） |
| IGW を通ってインターネットへ | 1500 バイト |
| Site-to-Site VPN | 1500 バイト（IPsec のヘッダーの分、中に入れられるのはさらに小さい） |

VPC の中では 9001 バイトで送れても、Site-to-Site VPN でオンプレミスへ行く通信なら、Path MTU は VPN の値まで下がる。

Path MTU を超えるパケットは、途中で分割されるか、DF（Don't Fragment）ビットが立っていれば破棄されて ICMP で送信元に知らされる。この ICMP を手がかりに送るサイズを下げる仕組みが PMTUD（Path MTU Discovery）。ただ、ファイアウォールやセキュリティグループ、NACL で ICMP が止められていると知らせが届かず、大きいパケットだけが黙って捨てられる。小さい通信は通るのに大きいデータだけ届かないときは、MTU を疑う。対策は、送信元や経路の途中で MTU や TCP の MSS を小さくしておくこと（詳しくは VPN と MTU の記事を参照）。AWS では、ICMP の「Fragmentation Needed」をセキュリティグループや NACL で許可しておくことも勧められている。
