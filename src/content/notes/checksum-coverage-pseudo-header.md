title: "IP のチェックサムはヘッダーだけを守り、TCP と UDP は IP アドレスを含む疑似ヘッダーまで含めてデータ全体を守る"
date: 2026-10-25
tags: [network, tcp]
---

チェックサムでどこまでを守るかは、プロトコルによって違う。IPv4 のチェックサムは IP ヘッダーだけを守る。TCP と UDP は、自分のヘッダーとペイロードに加えて、IP アドレスなどを並べた「疑似ヘッダー」も計算に含める。

| | チェックサムの計算に含める範囲 |
| --- | --- |
| IPv4 | IP ヘッダー |
| TCP / UDP | 疑似ヘッダー + ヘッダー + ペイロード |

IP の役目は、パケットを宛先まで届けることで、中身には関わらない。ペイロードが正しいかどうかは上位の層に任せる。そのため、IP のチェックサムはヘッダーだけを対象にしている。中身まで確かめると、ルーターを通るたびの処理が重くなるという事情もある。

ヘッダーには TTL も含まれていて、TTL はルーターを通るたびに1つ減る。そのため、IP のチェックサムもルーターごとに書き換わる。ただし、このチェックサムは足し算だけでできているので、変わった部分の差分を反映するだけで更新でき、ヘッダー全体を計算し直さなくてよい。

一方、TCP と UDP は疑似ヘッダーを使う。疑似ヘッダーは実際のセグメントの中には存在せず、チェックサムを計算するときにだけ、ヘッダーの前に置いたものとして扱う。

```
| 送信元 IP アドレス | 宛先 IP アドレス | 0 | プロトコル番号 | TCP/UDP の長さ |
```

L4 のプロトコルが、下の層の IP アドレスを持ち出すのは、層を分ける考え方からすれば筋が悪く、レイヤー違反といわれる。それでもこうしているのは、届け先の間違いに気づくため。IP ヘッダーの宛先アドレスが途中で壊れ、運悪く IP のチェックサムでも見逃されると、パケットは別のホストに届いてしまう。受け取ったホストは IP として問題がないので、中の TCP を取り出して、ポート番号を見てアプリケーションに渡してしまう。TCP のチェックサムに IP アドレスが含まれていれば、ここで不一致になり、間違って届いたセグメントを捨てられる。メールで、宛先はヘッダーに書いてあるのに、本文の1行目にも「○○様」と書いておけば、送り先を間違えたときに受け取った人が気づける、というのに似ている。

TCP ではチェックサムは必須。UDP では、IPv4 の場合はチェックサムを使うかどうかを選べる。使わないときは、チェックサムの欄をすべて 0 にする。ただし、IPv6 には IP ヘッダーのチェックサムがない。そのため、IPv6 の上の UDP では、原則としてチェックサムが必須になっている。
