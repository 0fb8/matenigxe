---
title: "SNMP の MIB は1つではなく、標準の MIB-II・RMON MIB とベンダー独自の MIB がある"
date: 2026-10-10
tags: [network, snmp]
---

SNMP で扱う情報は MIB（Management Information Base）として定義される。MIB は書き方こそ決まっているが、1種類だけではない。標準の MIB-II や RMON MIB のほかに、ベンダーが独自に作った MIB もたくさんある。

どの MIB も同じ1本の OID の木の中に置かれていて、置かれる枝で種類が分かれる。

| MIB | OID の枝 | 内容 |
| --- | --- | --- |
| MIB-II | `1.3.6.1.2.1` | システム情報、インターフェース、IP、TCP、UDP など基本的な項目 |
| RMON MIB | `1.3.6.1.2.1.16` | プローブが集めたトラフィックの統計 |
| ベンダー独自（プライベート MIB） | `1.3.6.1.4.1.<企業番号>` | 機種ごとの温度、ファン、独自機能など |

MIB-II はほとんどの機器が対応している基本の MIB。そのため、「SNMP の MIB」と言うとき、実際には MIB-II を指していることも多い。とはいえ、MIB が MIB-II だけだと思いがちだが、MIB-II は標準の MIB の1つにすぎない。

RMON（Remote Network Monitoring）MIB は、離れたネットワークのトラフィックを監視するための MIB。ふつうの SNMP では、マネージャが細かい値を何度もポーリングして集計しなければならない。RMON ではプローブ（専用機器や、RMON に対応したスイッチ）がそのセグメントを流れるトラフィックを自分で集計して、記録しておく。マネージャは集計済みの結果を受け取るだけで済むので、WAN を通じた監視でも通信量を抑えられる。

| | 監視する範囲 |
| --- | --- |
| RMON1 | データリンク層（Ethernet のフレーム数、エラー、ホストごとの統計など） |
| RMON2 | ネットワーク層からアプリケーション層まで（IP アドレスごと、プロトコルごとの統計など） |

ベンダー独自の MIB を使うには、ベンダーが配っている MIB ファイルをマネージャに読み込ませる。そうすると、数字だけの OID が名前つきの項目として表示されるようになる。
