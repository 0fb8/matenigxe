---
title: "SNMP はマネージャが MIB の OID を指定して機器の情報を集めるプロトコルで、ポーリングは UDP 161、トラップは UDP 162"
date: 2026-10-10
tags: [network, snmp]
---

SNMP（Simple Network Management Protocol）は、マネージャ（NMS）がルーターやスイッチなどのネットワーク機器（エージェント）の状態をまとめて管理するための標準プロトコル。マネージャから機器に問い合わせるポーリングには UDP 161 番を使う。機器からマネージャへ知らせるトラップには UDP 162 番を使う。

機器が持つ情報（CPU 使用率、インターフェースの通信量、稼働時間など）は、MIB（Management Information Base）という木構造に整理されている。木の根から目的の項目までのパスを数字で表したものが OID で、マネージャはこの OID で取りたい項目を指定する。

```sh
# 稼働時間（sysUpTime）を取得する
snmpget -v2c -c public 192.0.2.1 1.3.6.1.2.1.1.3.0
```

| 操作 | 方向 | ポート | 内容 |
| --- | --- | --- | --- |
| GET / GETNEXT / GETBULK | マネージャ → エージェント | UDP 161 | 値を読む（定期的なポーリング） |
| SET | マネージャ → エージェント | UDP 161 | 値を書き換える |
| TRAP | エージェント → マネージャ | UDP 162 | 異常をすぐに知らせる。応答はない |
| INFORM | エージェント → マネージャ | UDP 162 | TRAP と同じだが、マネージャが応答を返す |

SNMP の M は Management（管理）で、SET を使えば設定も変えられる。ただ実際は、ほとんど監視のために使われている。

トラップは UDP なので、届かなくても気づけないのではと心配になる。そのために v2c から INFORM が加わった。マネージャから応答が返らなければ、エージェントが送り直す。

| バージョン | 認証 | 暗号化 |
| --- | --- | --- |
| v1 / v2c | コミュニティ名（平文で流れる） | なし |
| v3 | ユーザーごとの認証 | あり |

v1 と v2c では、パスワードにあたるコミュニティ名がそのままネットワークに流れる。そのため、安全性を求めるなら v3 を使う。
