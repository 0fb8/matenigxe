---
title: "AWS RAM はあるアカウントのリソースをコピーせずにほかのアカウントから使えるようにする仕組みで、Organizations の中なら組織や OU 単位で共有できる"
date: 2026-11-21
tags: [aws]
---

AWS RAM（Resource Access Manager）は、あるアカウントが持っているリソースを、ほかのアカウントからも使えるようにする仕組み。名前に入っている RAM は、ハードウェアのメモリとは関係ない。リソースはコピーされず、持ち主のアカウントにある1つのものを、共有先のアカウントがそのまま使う。

共有するときは、持ち主のアカウントでリソース共有を作り、共有するリソースと共有先を指定する。持ち主は元のアカウントのままで、共有先ができる操作は、共有に付けた権限の範囲に限られる。

共有先には次のものを指定できる。

| 共有先 | 承認 |
| --- | --- |
| Organizations の組織全体 | 不要（Organizations との共有を有効にしている場合） |
| 組織の中の特定の OU | 〃 |
| 個別のアカウント（組織の外も可） | 共有先が招待を承認する |

組織や OU を指定しておくと、あとからその OU に入ったアカウントにも自動で共有される。アカウントが増えるたびに共有をやり直さなくてよいので、Organizations の中では特に便利。ただし、リソースの種類によっては組織の中でしか共有できないものもある。

共有できるリソースには、次のようなものがある。

- VPC のサブネット（複数のアカウントが1つの VPC の中にリソースを置く）
- Transit Gateway（各アカウントの VPC を、1つの TGW にアタッチする）
- Route 53 Resolver のルール
- License Manager のライセンス設定

たとえば、組織の中にライセンス管理専用のアカウントを作り、ライセンス設定をそこにまとめておく。各業務やプロジェクトのアカウントは、そのライセンス設定を RAM 経由で使う。こうすると、ライセンスの残り数を1か所で管理できる。
