---
title: "LLM に実際に入力されるのはコンテキストで、セッションはアプリが過去のやり取りを管理するために用意した単位にすぎない"
date: 2026-11-08
tags: [ai]
---

LLM が1回の呼び出しで受け取る入力の全体を、コンテキストと呼ぶ。セッションは、アプリが過去のやり取りをまとめて管理するために用意した単位で、モデル自身はセッションという概念を知らない。モデルが見ているのはコンテキストだけだ。

LLM は状態を持たず、入力を受け取って出力を返す一往復しかできない。利用者が打った文章がそのままモデルに送られるわけではなく、間にアプリが入る。アプリは、システムプロンプトなどいろいろな情報を足してコンテキストを組み立て、モデルに渡す。会話が続いているように見えるのも、アプリが過去のやり取りを毎回コンテキストに入れているからだ。どこまでを「過去のやり取り」とするかの区切りとして、アプリはセッションを使う。

ここでいうモデルとアプリは別物だ。たとえば OpenAI の場合、モデルは GPT シリーズで、ChatGPT はそれを使うアプリの名前だ。Claude や Gemini は、モデルとアプリに同じ名前が使われているので紛らわしいが、区別は同じだ。

コンテキストには長さの上限があり、これをコンテキストウィンドウという。上限は、モデルが学習時に扱った長さや、長くなるほど計算量とメモリが急に増えることから決まる。そのため、モデルの性質にも関わる制約だ。モデルが出力するぶんも、この枠に含まれる。上限を超えたリクエストは、API の側でエラーになる。

このため、セッションとコンテキストの中身は一致しない。

| | 例 |
| --- | --- |
| セッションにはあるが、コンテキストに入らない | 会話が長くなり、古いやり取りを要約に置き換えた（圧縮した）ときの元の発言 |
| セッションにはないが、コンテキストに入る | システムプロンプト、メモリ、RAG で検索してきた文書、道具の定義 |

アプリの仕事は、セッションやほかの情報源から、その時点で必要なものを選んで、上限の中に収まるコンテキストを組み立てることだと言える。Claude Code のようなエージェントハーネスも、この点では同じだ。そのうえで、モデルが求めた道具を実行し、その結果をコンテキストに足して、また呼び出すことを繰り返す。
