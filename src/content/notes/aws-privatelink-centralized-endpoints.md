---
title: "PrivateLink はサービスと利用者 VPC のインターフェース型エンドポイントをつなぐ仕組みで、エンドポイントを1つの VPC に集めるなら PHZ を自分で作って各 VPC に関連付ける"
date: 2026-11-22
tags: [aws, network, dns]
---

PrivateLink は、あるサービスを別の VPC から AWS のバックボーン経由で使えるようにする仕組み。サービスを提供する側と、利用する側の VPC に置くインターフェース型エンドポイントの2つでできている。利用者の VPC がたくさんあるときは、エンドポイントを1つの VPC に集め、名前解決のための PHZ（プライベートホストゾーン）を自分で作って各 VPC に関連付ける。

| 構成要素 | 置く場所 | 中身 |
| --- | --- | --- |
| サービス | 提供する側 | S3 などの AWS のサービスや、自分やサードパーティーが作ったサービス |
| インターフェース型エンドポイント | 利用する側の VPC のサブネット | ENI なので、プライベート IP アドレスとセキュリティグループを持つ |

PrivateLink はエンドポイントの別名でもバックボーンの別名でもなく、この2つをつなぐ仕組み全体の名前。通信は利用者側から始めるもので、提供する側から利用者の VPC へ通信を始めることはできない。

名前解決は、ふつうは何もしなくてよい。エンドポイントを作ってプライベート DNS を有効にすると、利用者からは見えない PHZ が自動で作られ、その VPC に関連付けられる。この PHZ には、サービスのいつもの FQDN（たとえば `ssm.ap-northeast-1.amazonaws.com`）をエンドポイントのプライベート IP アドレスに解決するレコードが入っている。そのため、VPC の中ではいつもの FQDN を指定するだけで、エンドポイント経由で使える。

ただ、エンドポイントは ENI なのでサブネットに置き、マルチ AZ なら AZ の数だけ要る。たとえばサービス 10 個を VPC 50 個から使うと、AZ が2つなら ENI は 1000 個になり、ENI ごとの料金がかさむ。そこで、エンドポイントを1つの VPC に集め、各 VPC からはピアリングや TGW でその VPC まで行って使う構成がある。ゲートウェイ型エンドポイントはピアリングや TGW の先からは使えないが、インターフェース型エンドポイントはただの ENI なので使える。

この構成で問題になるのは名前解決。自動で作られる PHZ は、エンドポイントを置いた VPC にしか関連付けられない。ほかの VPC でサービスの FQDN を引くとパブリック IP アドレスが返ってしまい、IGW や NAT Gateway のほうへ出ていこうとする。そこで、エンドポイントのプライベート DNS は無効にしておき、サービスの FQDN をエンドポイントに向けるレコードを入れた PHZ を自分で作って、全部の VPC に関連付ける。各 VPC の Route 53 Resolver が関連付けられた PHZ を見てその場で答えるので、Resolver のインバウンドやアウトバウンドのエンドポイントは要らない。

オンプレミスからもこのエンドポイントを使わせたいときは、オンプレミスには PHZ を関連付けられないので、インバウンドエンドポイントを置いた DNS 用 VPC を用意し、そこにも PHZ を関連付ける。エンドポイントを集める VPC と DNS 用 VPC は役割が別だが、1つの VPC にまとめて「共有サービス VPC」と呼ぶことが多い。
