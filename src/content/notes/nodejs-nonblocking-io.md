---
title: "Node.js は、非同期が当たり前という JavaScript の文化をサーバーに持ち込み、待ち時間でスレッドが詰まる問題に応えたランタイム"
date: 2026-11-03
tags: [programming]
---

Node.js（2009 年）は、JavaScript をブラウザの外、とくにサーバーで動かすためのランタイムだ。ブラウザの JavaScript にもともとあった「待たずに、終わったら知らせてもらう」という書き方をサーバーに持ち込み、たくさんの接続を少ない資源でさばけるようにした。

2000 年代後半には、タイムラインのように画面の一部を更新し続ける Web サービスが増えた。スマホの普及で、接続の数も増えていった。当時のサーバーは PHP・Ruby・Java などで書かれ、1つのリクエストに1つのスレッドを割り当てる作りが一般的だった。この作りでは、データベースや外部 API の応答を待つ間もスレッドがふさがる。接続が増えるほど、待っているだけのスレッドでメモリが埋まっていく。

これらの言語でも、待っている間にスレッドを別の仕事に回す非同期処理（ノンブロッキング I/O）は書けた。しかし、既存のライブラリの多くは、応答が来るまでそのまま待つ（ブロッキングする）作りだった。1つでもそういうライブラリを使うと、そこでスレッドが止まってしまう。

一方、ブラウザの JavaScript は、通信やタイマーの処理を「終わったらこの関数を呼んで」とコールバックで書くのが当たり前だった。1本のスレッドがイベントループで、終わった処理から順に続きを実行するイベント駆動の考え方だ。しかもサーバー向けのライブラリがまだなかったので、最初から全部をノンブロッキング前提で作れた。そこで、Chrome の JavaScript エンジン V8 を使ってサーバー用のランタイムを作ったのが Node.js だ。

ブラウザの JavaScript というと DOM 操作を思い浮かべがちだが、DOM はブラウザというランタイムが提供する機能で、言語そのものの一部ではない。Node.js には DOM がない。その代わりに、ファイルやネットワークを扱う機能がある。

| | ブラウザ | Node.js |
| --- | --- | --- |
| 共通するもの | JavaScript の文法、イベントループと非同期の書き方 | 同左 |
| ランタイムが提供するもの | DOM、`fetch`、`localStorage` など | ファイル、ネットワーク、プロセスなど |

Node.js が広まったことで、ほかにも良いことがあった。

- **フロントエンドとバックエンドを同じ言語で書ける**。動く場所もやることも違うが、文法が同じなので覚えることが少なくて済む。
- **フロントエンド開発のツールが増えた**。フロントエンドの技術者が慣れた言語でツールを書けるようになり、npm でパッケージを配る文化も育った。Vite、webpack、ESLint などは Node.js の上で動く。
