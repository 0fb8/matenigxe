---
title: "ビルドは、書きたい言語と実行環境が解釈できる形との差を埋める変換で、ブラウザ向けではファイルをまとめて小さくする最適化も兼ねる"
date: 2026-11-03
tags: [programming]
---

ビルドは、人間が書きやすい言語で書いたコードを、実行環境（ランタイム）がそのまま解釈できる形に変換する作業だ。言語の進化に実行環境が追いついていないところに、ビルドが現れることが多い。

代表は C/C++ や Rust のコンパイルだ。CPU は機械語ならそのまま実行できるが、機械語は人間には書きにくい。そこで高級言語が生まれた。一方で CPU が解釈できる命令の形は、性能が桁違いに上がった今も基本的に変わっていない。だから高級言語で書いたコードは、コンパイルで機械語に直してから CPU に渡す。

同じ構図はブラウザでも起きている。ブラウザが解釈できるのは素の JavaScript だ。しかし Node.js の登場でフロントエンドの開発が発展し、ブラウザ向けのコードにも次のようなものを使いたくなった。

- **TypeScript**: JavaScript に型を足した言語。ブラウザは TypeScript を解釈できない。
- **npm のパッケージ**: `import "react"` のようにパッケージ名だけで読み込む書き方。Node.js は `node_modules/` から探してくれるが、ブラウザにはその仕組みがない。
- **JSX** や、古いブラウザがまだ対応していない新しい JavaScript の構文。

そこで、ビルドで素の JavaScript に直してからブラウザに渡す。ブラウザ向けのビルドは、速くするための最適化も兼ねている。

| 処理 | 内容 |
| --- | --- |
| トランスパイル | TypeScript や JSX、新しい構文を、ブラウザが解釈できる JavaScript に直す |
| バンドル | 何百ものファイルを少数のファイルにまとめ、読み込みの回数を減らす |
| 圧縮（minify） | 空白やコメントを除き、変数名を短くしてファイルを小さくする |

逆に、実行環境が書いた言語をそのまま解釈できるならビルドは要らない。Python は、インタプリタがソースコードをそのまま受け取って実行する。内部ではバイトコードに変換しているが、利用者がビルドを意識することはない。Node.js 上で JavaScript を動かすときも、`node_modules/` を自分で探せるのでビルドは不要だ。

TypeScript は JavaScript に直さないと動かないと思いがちだが、今は直接実行できる環境も増えている。Deno や Bun は TypeScript をそのまま実行でき、Node.js も 22.6 以降で型の部分を取り除いて実行できるようになった（23.6 からは標準で有効）。ただし、どれも型を取り除いて JavaScript として動かすだけで、型チェックはしない。型が合っているかどうかは、今も `tsc` などで別に確かめる。TypeScript はもともと「型を消せば JavaScript になる」ように設計されているので、実行するときに型の情報は要らないのだ。
